## 实现与边界

业务文件只有 `robot_control/control_comply.cpp`、`control_comply.h` 和新增
`forward_brake_control.inc`。后者包含在原翻译单元中，不修改 CMake 或消息结构。
其他新增/更新文件均为 control 测试、说明和项目要求的 workflow 日志。

- 电机仍是目标速度接口：`throttlePercent = 13.5 × speed_cmd`，沿用整数截断。
  原导航速度 +0.5 上限、5%低速保底、曲率公式、导航速度×4秒预瞄、几何抗噪及30周期释放保持。
  不改横向控制、planning、can_comm、canbus、参数文件、节点订阅或20Hz周期。
- `/can_msg.brakePercent != 0` 是实际液压接入，不能用 control 请求代替实际状态。
  数值不是压力，也不假设与减速度线性。CAN 车速仍不参与控制。
- 普通减速先降低电机给定。导航速度按约0.1秒差分并经0.2秒低通得到实测加速度；
  0.6秒观察期后，只有实测减速度仍不足、且此前规划原始 `desireSpeed` 下降，才累计补刹积分。
  液压所需减速度参考为 `clamp((v-speed_cmd)/2s, 0, 0.8m/s²)`，增长最多0.5m/s³，
  回落最多0.8m/s³。这只约束液压协调参考，不声称限制整车实际 jerk。
- 普通首请求3%，等待实际正反馈后再小步调整；反馈首次接入至少0.5秒后，每0.5秒最多
  加1个百分点或减2个百分点，普通上限15%。接入前不随20Hz帧率堆叠补刹。
  这些是工程初值，不是从 bag 辨识出的非线性逆映射或液压死区。
- 用当前实测减速度进行1.7秒前推，预测接近目标，或速度误差≤0.12m/s时提前撤液压。
  撤请求不等于实际释放；在途、接入、等待释放时均禁止同时驱动。
  曾发正请求必须见过正反馈，随后由递增时刻的实际零反馈连续确认至少0.15秒，
  且距最后正请求至少1.8秒，才允许恢复电机给定。单条零反馈加重复控制周期不能放行。
- 积分保持 `I += 正速度误差 × dt`，单位m。参数
  `/robot/control/brake_integral_threshold` 默认0.1m，饱和上限仍为两倍门槛、默认0.2m。
  积分仅为启动门槛，不再使用旧的 `速度误差×15` 作为普通刹车力度。
  等待响应/卸压时不积累，电机减速已足够时清积分。曲率或本地故障限速单独下降仍不能启动普通积分。
- 下降请求允许相对本次最低规划目标不超过0.1m/s的小幅回升，避免毫米每秒级波动立即取消制动过程。
  累计回升超过0.1m/s、达到原规划目标或任务/路线/挡位/模式等改变，结束普通请求。
  上述复位不会抹除实际液压在途记忆。离开D不修改R/N输出。

普通 D 循迹末停仍要求已完成任务、目标近零、距离在[0,0.5)m、实际速度≤0.35m/s、
导航/CAN新鲜且无既有安全异常；从已有制动连续承接，最低5%，按10个百分点/秒建立，
运动阶段普通上限30%。导航停稳≤0.03m/s并持续确认0.3秒后进入原80%保持；
2秒仍未停稳回到80%。已有70/100%安全制动不会被柔化降低。其他任务/异常末停沿用强停车。

## 独立安全与执行故障

规划 safety、CAN 急停、正常行驶分支GNSS急停等独立安全请求立即输出100%，
不等待普通观察期、积分、预测或15%上限。D行驶分支围栏/横向偏差仍70%，
与更强制动取大，不能把100%覆盖为70%。所有D早返回的最终制动均在发布前登记在途状态。

液压执行故障触发100%并锁定，不能靠超时恢复驱动：

| 故障条件 | 处理时机 |
| --- | --- |
| 首个正请求没有任何非零实际响应 | 2秒 |
| 仍在持续正请求，曾响应过但实际反馈持续归零 | 2秒 |
| 撤销后没有完成实际释放确认 | 撤销起3秒 |
| 液压过程中CAN/导航接收数据过期 | 年龄>0.2秒先保持上一最终刹车、禁止驱动；持续过期0.5秒后故障 |
| 液压执行过程中时钟回跳或非法 | 保留在途记忆并进入故障，重建观测时间基准 |
| 普通制动15%饱和且实际减速仍明显不足 | 最后加量后先观察1.8秒；误差>0.5m/s、减速度短缺>0.2m/s²持续1秒后故障 |

无液压参与的正常D直线，不新增“0.2秒数据过期立即100%”的停车策略；新数据失效时不能新建普通补刹。
手动模式下 control 指令不会被记为已执行的自动液压请求。
故障只允许手动D、导航停稳≤0.03m/s、连续新鲜零制动反馈至少0.5秒后清除；
单次零反馈、规划恢复、切R再切D都不能绕过故障。R挡行为不受该锁定影响。

以上时延来自工程初值和现有 bag 的观测范围，不是执行器最坏时延保证。
尤其1.8秒驱动互锁期间，电机零给定自身仍会减速，可能带来欠速；需要车端验证。
CAN消息没有制动源时间戳，持续重复旧测量仍可能被当成新回调，无法仅在control内识别。

## 为什么不采用现阶段拟合的制动逆模型

指定 bag 最大实测车速3.1643m/s，没有5m/s制动覆盖。
在纯电机制动样本上，带输入延迟和饱和的一阶模型，留出数据加速度MAE仍0.744m/s²、
RMSE1.068m/s²；存在9段“实际速度低于过去一秒全部给定、但仍继续明显减速”的符号反例。
零给定且液压未接入有效样本仅2.48秒，不能可靠标定零油门减速度。
液压反馈级别混杂了电机给定、车速、延迟，不能直接生成可信的百分比→净减速度表。
因此本次使用实测减速度和执行状态协调，不把未辨识的模型作为前馈或安全判据。

普通目标突然降低时，现有硬限速要求电机给定立即降低；本次不通过抬高规划/曲率限速平滑电机目标。
单靠本轮control改动，不能保证任意突降目标下的舒适性或紧急停车距离。
5m/s稳态给定验证也不代表5m/s制动已通过实车验收。

下游仍按现状执行：canbus可能将急停100%覆盖为80%，制动时清转角；can_comm没有完整指令年龄链。
按用户要求本轮没有修改这些模块，control的紧急请求不能等同于最终整车紧急制动能力。

第三条的基准目录来自上方备份解包，必须使用完整改前control目录，不能指向当前源码。
新测试通过公开回调和真实最终发布检查：电机已足够/确实不足、延迟接入/退出、提前撤请求、
重复时间/新反馈确认、规划微波动、路径任务复位、手动接管、故障恢复、无效制动、低速末停及安全抢占。
独立曲率用例重建控制对象，避免上一停车用例的真实液压状态泄漏到无关曲率场景；
真实跨挡/跨任务状态由新的连续序列专项覆盖，未放松曲率数值或R消息断言。

旧 `verify.py` / `brake_request.cpp` / `launch_speed.cpp` 保留历史断言，包含原比例补刹和立即恢复油门预期，
不作为本轮新反馈制动的验收入口；本轮不宣称旧套件通过。

本次新增运行逻辑均为固定标量状态，导航/CAN更新及每周期协调为O(1)，没有新增路径扫描、
容器或算法堆分配。`getCached`沿用积分门槛；异常日志限流1Hz，不增加正常高频日志。
本机执行耗时不代表车端CPU或真实机械响应，本轮没有车端性能测量。

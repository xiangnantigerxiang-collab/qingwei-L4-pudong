# D挡曲率限速独立复核：公式成立，但当前方案未满足全部需求

日期：2026-09-21。复核对象是[上一版公式及验证](curve_preview_20260921.md)。
后续用户实车确认直线约1.9m/s及顿挫；现已修正噪声曲率入口，见[修复与验证](curve_noise_fix_20260921.md)。
以下保留本次审计时的证据和未修复边界。
本轮没有修改业务源码、标定、地图或现有测试断言；新增诊断回放和本报告，并更正验证状态。

**结论：同一曲率下的公式计算正确，但6m原始曲率取最大值会放大实车路径噪声，
已经复现近直线限速低于旧0.3的反例。不能把既有专项通过等同于满足“直线保持0.6、
转弯比旧0.3提高约20%”的完整要求。**

## 1. 已复现：近直线路径被6m曲率峰值过度限速

位置：[ForwardCurveLimitSpeed](../../src/robot_control/control_comply.cpp)，
取峰值在680–720行，系数计算在722–729行。原曲率生成在CalcuPathCurve的773–806行。

复用工程同级`rosbag_analysis_20260921_112431_937_121827/`的真实规划坐标、导航反馈和
已有几何匹配结果，分别编译当前源码、旧0.6算法及同一旧算法的0.3版本。
三者均保留当前D×13.5、当前车速+0.5、相同输入及制动逻辑，只比较曲率算法差异。
每个控制周期都先更新实际最近点，再在副本中读取限速，避免诊断改变曲率历史。

记录相对时间90.0–94.4s，共88帧，规划均为3m/s；这些帧的匹配曲率误差全部为0，
横向误差匹配最大差约1.47e-8m。曲率上限结果：

| 算法 | 曲率上限范围 m/s | 限制规划3m/s的帧数 |
|---|---:|---:|
| 原0.3，原平均曲率 | 2.174–3.272 | 74/88 |
| 原0.6，原平均曲率 | 4.348–6.543 | 0/88 |
| 新分段公式，6m最大曲率 | 1.720–2.026 | 88/88 |

新上限在这88帧全部低于旧0.3。以94.29873488s、规划933为例：

| 项目 | 原0.3 | 原0.6 | 新算法 |
|---|---:|---:|---:|
| 曲率上限 m/s | 2.204778 | 4.409556 | 1.729173 |
| 与规划及车速+0.5取小后的给定 m/s | 2.204778 | 3.000000 | 1.729173 |
| 当前标定下的整数油门字段 % | 29 | 40 | 23 |
| 液压刹车字段 % | 0 | 0 | 0 |

该帧导航车速为2.52m/s，6m内曲率峰值0.04334391 1/m，原平均曲率0.01851454 1/m。
对实际预瞄窗口内60个样条点做独立直线拟合，最大横向残差仅9.04mm；
局部二次拟合的中心曲率约0.000714 1/m，仅用于说明整体几何与短距离峰值差异。
这些数值不是标定推荐，也不证明任意二次拟合都可替代现有曲率。

原因是原CalcuPathCurve由约1.1m内的航向变化计算曲率，对毫米级位置起伏敏感。
新算法保留这个估计器，把原平均曲率换成最大值，并对较大的峰值使用0.36。
30次峰值历史只延缓释放，不能消除当周期噪声峰值。

本回放固定使用记录的导航反馈，不是车辆动力学闭环，不能把1.729m/s上限写成新算法实测车速。
全段3551帧亦已生成诊断结果，但部分帧的路径匹配不精确；以上结论使用匹配准确的88帧。

## 2. “提高20%”仅是相同曲率下的局部结论

0.36/0.3=1.2正确；但旧算法用平均曲率，新算法用峰值，输入已经不同。
在新算法使用0.36的范围内，有：

```text
v_new / v_old03 = 1.2 * sqrt(k_old_mean / k_new_effective)
```

因此，当新有效曲率大于旧有效曲率的1.44倍，新上限反而低于旧0.3。
以上真实路径已经触发这种情况。提前看到急弯而更早限速符合预瞄目的，
但近直线路径噪声导致的普遍降速不符合用户要求，两者应分别验收。

此外，现有阈值是初始选择，未由实车数据拟合：

| 相同有效半径 | 新公式相对旧0.3 |
|---:|---:|
| <=50m | +20% |
| 60m | +30.10% |
| 80m | +60.00% |
| 100m | +79.26% |
| >=200m | +100%，即0.6系数 |

所以“全部转弯都提高20%”并不成立。独立对数扫描10^-12至10^4 1/m，
100001个输入的单调性和上下界检查通过；0.005、0.02两接点的限速及一阶导数连续。
数学插值没有算错，曲率来源和需求覆盖需要修正。

## 3. 已复现：短路径完整入口存在原有越界

位置：[CalcuPathCurve](../../src/robot_control/control_comply.cpp)的777、805–806行。
只排除size<=1，却对剩余路径访问`path_list.at(size - 13)`。

真实消息入口复现：20个原始点，`x=i*0.05`、`y=0.2`，路径长0.95m。
它能通过原始点数检查及过滤，样条后只有9点，访问size-13时抛出`std::out_of_range`。
30组不同点数/间隔输入中14组触发；旧0.6源码得到完全相同结果，确认是原有问题。

此前短路径检查直接调用ForwardCurveLimitSpeed，绕过了SetPathPlanData与曲率生成，
因此不能证明完整消息链支持短路径。复核没有擅自修改D/R共用的几何函数。

## 4. 最终输出与预瞄作用的边界

- 当前车速+0.5m/s已恢复，在曲率限速前取小；既有专项重跑12589项通过。
  它约束加速给定，不能保证入弯时车速已下降。
- 6m按真实折线路程累计，从导航参考点的路径投影起算；已有边界、移动窗口、
  左右圆弧和掉头折线检查通过。它限制参与计算的曲率位置，不是物理减速距离保证。
- 规划目标不下降时，曲率限速不会自行启动积分液压补刹，这是此前明确保留的行为。
  示例帧2.52m/s反馈、1.729m/s给定、刹车0%，与代码门控一致。
  车辆是否能在6m内达到弯道目标，需要电机速度环和实车减速响应数据。
- 低速5%保底位于曲率取小之后。诊断注入曲率4 1/m、当前速度0时，上限0.18m/s，
  最终仍输出5%，对应当前标定约0.370m/s。这个极端边界下曲率上限会被保底提高；
  这是既有优先级，不能把当前公式描述为所有条件下的最终硬上限。

## 后续修正的验收依据

应先处理用于限速的曲率噪声，避免近直线被局部尖峰判为小半径弯道；再以相同真实轨迹
比较旧0.3、旧0.6和新算法的最终给定。任何空间平滑都必须另外检查入弯、左右切换和掉头，
确保没有把真实急弯一并抹掉。仅继续降低或提高系数不能解决曲率输入失真的问题。

完整入口应补上不足13点的边界验收，并明确曲率上限与5%保底的优先级。
沿用此前制动要求时，不能通过“新公式测试通过”宣称已经保证6m内实车完成减速。

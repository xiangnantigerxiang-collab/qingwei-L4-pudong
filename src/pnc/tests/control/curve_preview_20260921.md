## 标定与使用口径

用户实车确认统一0.6时直线稳定、转弯/掉头过快，并选择弯道相对旧0.3提高约20%。
本次按该目标构造分段连续公式，未用实车数据进行统计拟合。

设本次车辆前6m的最大绝对曲率为kp，最近30次kp均值为kh（未填项按零）：

```text
k = max(kp, kh)
t = clamp((k - 0.005) / 0.015, 0, 1)
c = 0.6 - 0.24 * t*t * (3 - 2*t)
v_curve = c / max(sqrt(k), 0.001)   // m/s；k为1/m
```

有效半径R=1/k。R>=200m沿用0.6；R<=50m采用0.36，即同曲率下旧0.3的1.2倍，
也是统一0.6的60%。50<R<200m连续过渡，两个接点系数斜率均为零。
全部标定常量写在函数开头，需要重编robot、重启control；没有新增ROS参数读取。

## 6米预瞄与速度差上限

- 起点是导航参考点在本周期最近点相邻线段上的投影；复用VehiclePoseCalculation的mKeyPoint。
- 顺路径索引方向，累计真实x/y折线距离6m；不按点数、数组首点或车辆周围6m圆选择。
- 取区间最大绝对曲率，起点与6m边界插值；不足6m取真实末点，重复点不增加路程，短路径不补零。
- 曲率本身仍由原CalcuPathCurve产生，本轮改变采样范围和限速公式，不重写曲率估计或横向算法。
- 峰值立即约束新急弯，30次历史均值仅延缓出弯释放，防止直线点/旧历史稀释新急弯。
  正常20Hz下全零输入最多约1.5s清除历史；停车、换挡、模式/路线/任务变化沿用原复位入口。
- 用户追加要求的原句已恢复：`if(delta > 0.5) speed_cmd = speed_now + 0.5;`。
  该限制在曲率前取小，然后仍经过故障限速、原5%低速保底、安全制动和最终挡位覆盖。
  这是基于当前导航速度的差值上限，不是按时间积分的加速度斜坡。
- 开工时已有的D×13.5、5/13.5保底与R×10/45%标定原样保留。曲率只降低电机速度给定，
  不自行触发规划下降积分补刹；预瞄6m不是实车已完成减速的保证。

固定曲率预瞄作为独立限速输入的设计口径可参考
[Nav2官方说明](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/controller_plugins/configuring_regulated_pp/#curvature-lookahead-dist)。
本次6m、0.36/0.6及两个曲率门限按用户需求和初始标定选择，没有移植其控制器。

## 验证结果与边界

1. C++11控制节点编译、链接成功；真实生产函数的12589项专项通过。
   覆盖正/负曲率、单调性、分段连续性、20%锚点、5.9/6/6.1m边界、车后点、移动窗口、
   非均匀点距、两种局部投影、边界插值、重复点、掉头沿线路程、短/空路径及非法值。
   包含真实左右圆弧经过规划消息过滤/样条/曲率再进入完整控制流程，以及恢复速度差上限的输出。
2. 规划下降积分请求7473项通过；曲率限速不会绕过原积分请求门控，独立安全优先级保持。
3. 改前与改后R弯道/直线/制动切换150条完整消息、D切R40条完整消息一致。
4. 为核对其他控制路径，另以“原开工源码只恢复用户要求的+0.5语句”为对照，
   191组既有场景、6486条完整控制消息一致（包括NaN字段同形态比较）。
   临时对照源码、编译命令与结果位于证据目录comparison_reference/。
5. 旧主控制套件原断言未改：开工基线133项通过、23项失败；改后带R/标定差分224项通过、
   相同23项失败。其失败包括D×15和+0.5的旧组合输出、旧交通灯停车预期。
   本次原样保留用户工作区的13.5标定及已不存在的交通灯分支，未为测试恢复无关业务。
   常规verify.py直接运行仍会遇到这些旧断言；--curve-preview是明确的专项入口，不表示旧全套通过。

本机没有ROS1，使用真实.msg生成的ROS桩。这些结果未覆盖Orin调度、车辆实际减速能力和循迹效果；
本轮未连接、部署或实车验收。

## 可复现命令

在工程根执行：

```bash

```

添加`--baseline-control <本轮改前完整control目录>`会核对R完整输出。
需要测曲率函数耗时，在已有构建后运行：

```bash
python3 -B src/pnc/tests/control/verify_curve_history.py --control-build /tmp/control_curve_preview --output /tmp/control_curve_benchmark --baseline-control <本轮改前完整control目录> --benchmark
```

生产C++11与include顺序保持。--curve-preview只构建既有节点/驱动并运行制动请求、曲率与速度差专项；
未改主控制套件原断言。旧基线的历史ResetLaunchSpeed兼容由专用宏保留，不影响生产。

## 时间复杂度与性能

原D入口固定30项历史+30点求和为O(1)。新入口复用当前最近点，检查至多两条相邻投影段，
再扫描6m内的P个点并求和30项历史：O(P+30)，最坏O(N)，N为总路径点数。
不能在任意点密度/重复点条件下称为O(1)。没有新增全路径最近点搜索、容器、实例成员、
动态分配或周期日志；历史固定30个double，任务/路线等复位入口保留。

同输入、固定主机CPU、每轮预热1000次/采样10000次，新旧交替5轮，以下为每轮统计量的中位数，单位μs。
benchmark只测曲率函数，不包括完整VehicleControl或新旧刹车逻辑；两条路径均按0.1m采样。

| 点数 | 版本 | P50 | P99 | 单轮最大值中位数 | 每次C++分配 |

|128|改前|0.049|0.055|0.421|0|

|1024|改前|0.048|0.054|0.104|0|

# 左二车道输入过滤验证（2026-09-20）

## 行为与范围

`robot/object.msg` 明确 `type=2` 为左二车道。planning 消费 `/perception` 和
`/perception/planning` 时新增剔除此类型，不依赖速度、方向或几何相交情况。
不修改上游消息及其发布者，也不增加消息副本、独立遍历或容器。

- `/perception`：在原循环中剔除左二，复用原 ID 标记表清理兼容四帧风险历史。
  尚未启用专用观测链时清理该历史；启用后原历史只供独立前扫描使用，保持原处理。
- `/perception/planning` 常规跟踪：有效整帧提交后，删除被新分类为左二的同 ID
  旧框与确认票数，不继续作为漏检目标外推。重复/乱序/冲突 ID/坏帧不部分提交删除。
- 起步观察：在原新帧缓存重建过程中跳过左二；全部目标被过滤的有效帧按空观测处理。
  其他车道及左一对向目标仍按既有周边距离检查；当前 1m 半径和 D 挡范围不改。

原有本车道、左一方向过滤、车道外规则、输入时效、急停解除迟滞、独立前后扫描、
区域限速、终点停车、闸机和人工急停保持原逻辑。删除某一目标不会直接清除其他来源的 safety。
已经建立的常规全局急停仍经过原清场迟滞解除，不能把“轨迹删除”理解成“当帧解除所有停车”。

## 复杂度与内存

新增条件在原遍历中执行，每个目标增加 O(1) 判断。N 为本帧目标数，H 为旧四帧风险
总目标数，A 为当前活动轨迹数；旧入口最坏仍 O(N+H)，新观测入口仍 O(N+A)，起步
观测仍 O(N)。左二帧会按需要进入原历史清理分支，清理的 O(H) 成本不能忽略。
不新增持久状态/容器；既有代数标记表的极少数计数回卷清零行为保持。

`perception_allocations.cpp` 对比同一输入：300 个目标、1,000 次预热后 Observe/Evaluate，
修改前后均 **0 次堆分配**，`PerceptionSafety::WorkingBytes()` 均为 **4,789,248 bytes**。
该数值是现有核心缓存统计，并非整进程 RSS 或整车内存峰值；生产没有新增分配点。

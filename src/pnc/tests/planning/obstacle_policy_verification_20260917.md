# planning 障碍物策略修改验证（2026-09-17）

按用户要求，生产修改仅限 `robot_path_plan` 的四个文件：
`safety/perception_safety.h`、`safety/perception_safety.inc`、`path_plan_comply.h`、
`path_plan_perception.inc`。消息、converter、control、monitor、参数和路径数据未改。

## 当前行为

- `/perception/planning` 的紧急碰撞按同一 ID 连续三帧真实风险观测确认。
  前两帧仅限制 `desireSpeed <= 0.6 * abs(can_msg.vehicleSpeed)`，第三帧才置 safety 并停车。
  60% 是每次评估的当前实际车速比例，不对上次命令反复乘 0.6；其他更低速度优先。
- 重复时间戳、重复规划、漏检外推、不同 ID 不能累计紧急票数；非紧急帧、漏检、跳过的
  未评估观测或超过既有 confirmation_gap 的间隔会中断连续确认。
  普通目标已经确认存在，不代表该目标下一次单帧紧急条件可以直接满制动。
  紧急三帧固定执行，普通目标的 confirmation_hits/time 与低分数加帧规则保持。
- 两个 perception 入口都忽略 type=3/4；type=0/1/2 保留，继续执行既有尺寸、几何检查。
  有效新帧中同 ID 变为车道外，立即清除其旧轨迹；旧兼容风险窗口同步删除该 ID，
  不允许旧车道内几何继续参与。坏帧不能部分修改已提交轨迹。
- 起步/T 区收到的是已过滤对象，其原有时间窗保持。独立前后扫描、超声、急停、
  闸机、任务停车、暂停、断网、区域限速、输入超时和紧急解除迟滞均保持。
- 为使上述确认不受路径点距影响，同时修复了首个普通余量相交后提前退出、漏查下一段
  紧急物理碰撞的问题。复用同一遍历，只继续检查紧急距离内后续段，仍受 128 段上限约束。

标记表使用一次性缓存；核心缓存 4,789,248 bytes（约 4.57 MiB），旧感知入口另加 128 KiB
标记表。相较改动前总增加约 0.75 MiB，不增加第二套关联/跟踪或周期文件、参数访问。

覆盖首次/第二/第三帧、既有稳定目标突然单帧危险、单帧误检消失、重复旧帧、漏检外推、
观测间隔、不同 ID、低分数、0/1/2/3/4 五种类型、车道分类切换、无效帧原子性、已有零速
和更低速度，以及起步/T 区输入。相邻段反例既测试独立 0.1/0.3/1m 分段，也通过真实
PublishReferPath → CheckForwardReferenceSafety → PublishPlanPath 检查 0.1/1m 原始点距：
前两帧均为 0.48m/s、safety=0，第三帧均为 0、safety=1（自车 0.8m/s）。

六种隔离变异分别为恢复单帧急停、不滤车道外、误滤左一/左二、恢复软相交提前 break、
保留车道外 ID 旧缓存、错误改为 80% 限速。均编译成功后被行为断言检出，生产源码未应用变异。

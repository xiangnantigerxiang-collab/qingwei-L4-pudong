# 2026-09-18 PNC 内部起步观察删除验证

按用户要求删除 PNC 内部的周边起步观察、T 路口观察和固定等待区停车。
删除对应实现分片、调用、接口、历史窗、任务/退化路径复位及专用几何辅助；
轨迹复用仅去掉起步观察通过条件，仍保留长度、碰撞及终点距离条件。

独立 `ultra_command` 及 `left1.csv`、`left2.csv`、`right.csv` 未改，
PNC 对 `/ultra/status/safe` 的读取保持。路径碰撞、前后扫描、新感知避障、闸机、急停、
断网、云端暂停、人工/短路径退化、区域限速、起步鸣笛和控制速度斜坡保留。

## 编译与行为检查

使用真实 `.msg` 生成的 ROS 桩，41 个规划及公共算法翻译单元编译、链接通过。

| 检查 | 结果 |
|---|---:|
| 单点区域限速 | 284 项通过 |
| 闸机安全覆盖 | 1,806 项通过 |
| 感知集成 | 265 项通过 |
| 起步观察删除、独立停车/声光及轨迹复用 | 756 项通过 |

当前源码可复现上述 3,111 项检查：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 src/pnc/tests/planning/verify_point_speed_limit.py \
  --output /tmp/planning-startup-removal-check
```

新增删除检查在未修改的旧实现上失败，失败原因为首周期仍被起步观察压为零速。

## 修改前后差分

使用开工时 PNC 副本与当前实现分别运行原有 387 组场景，两侧业务断言通过，
每侧记录 6,058 行完整发布消息、状态及参数事件。仅排除已删除的三个内部状态字段，
严格限制剩余差异为：

- 31 条路径发布、38 条消息快照：仅最终 `desireSpeed` 从观察零速恢复为原平滑速度或原低速。
- 33 条灯光参数事件：原观察报警 `7` 恢复为既有灯光命令 `0`、`3` 或 `8`。
- 其余消息字段、内部状态和参数事件一致。

源码核对确认 71 个保留方法有效 token 未变；其他方法仅移除上述观察依赖。
全部 14 个实现分片仍各包含一次。构建后四处转向灯注释发生变化，已保留，
并用构建记录的 SHA-256 和 token 对照确认不影响已测试代码。

范围核对确认 PNC 外 2,029 个文件/链接未变；PNC 内路径、参数、消息、控制和感知转换
共 142 个保护文件未变。全部修改限于 `src/pnc`，工程根目录记录未改。

开工副本及原始日志：`/tmp/pnc_remove_startup_20260918_41mlgrkd/`。
其中 `after-build/result.json` 记录编译与检查结果，`regression_comparison.json` 记录逐项差异，
`source_audit.json`、`scope_audit.json` 记录源码和范围核对；临时目录不保证长期保留。

本机桩编译使用 C++14 以适配主机 Boost，生产 CMake 仍为 C++11。
未执行 ROS1/Orin 实际构建、车辆节点运行或实车验证。

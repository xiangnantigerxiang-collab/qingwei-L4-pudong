# 2026-09-15 空帧、过期与发布安全复核

本次检查并修复 `robot_perception_convert` 中时序滤波的发布接入。独立滤波接口、
匹配规则、置信度公式及 HDMap SDK 均未修改。

## 检查结果与修复

| 场景 | 检查前行为 | 本次处理 |
| --- | --- | --- |
| 有效空 MarkerArray、仅文字标记、排除后为空 | 已作为空观测进入分母，降低历史目标置信度 | 保留并回归，目标最后真实观测满两秒后退出输出 |
| 正常持续来帧 | 已删除两秒过期前缀 | 统一由维护函数处理，保留 `>=2s` 边界 |
| 上游断流、连续 HDMap 失败或定位失效 | 过期清理依赖成功回调，本地缓存可能长期保留 | 在回调校验前和原有 100Hz 主循环维护，过期数据被清除 |
| 启动后尚无定位、定位停止更新 | 默认零值或旧的有限坐标可能参与转换 | 记录定位接收状态和时间，要求定位年龄在 `[0,2s)` 且有效字段有限 |
| 坐标转换、分类或滤波失败 | 全局 `mPerception` 可能留下半转换工作帧 | 使用局部工作变量，成功后统一提交；异常帧不进入有效历史、不发布 |
| 处理期间 ROS 时间回退或跨过两秒窗口 | 滤波可能返回旧帧或默认空消息，之后仍发布 | 发布前检查当前时间、当前帧和定位年龄、返回 header，以及零时间戳下的非空帧丢失 |
| 相同时间戳及滤波异常 | 已在成功后替换旧帧、失败时撤销追加 | 保留并测试，暂停时钟不增加历史条数 |

删除历史前缀后会清除基于旧窗口计算的本地结果；仍有效的原始帧保留，待下一真实有效帧
重算。维护函数不定时发布旧结果，也不生成带新时间戳的空心跳。

## 断流时不补发空消息的依据

`robot_path_plan/path_plan_node.cpp` 的 `PerceptionMsgCallBack` 用当前接收时间更新
`sysTime.msgPerception`；`T1Callback` 在感知接收间隔超过三秒时设置传感器故障位。
`robot_control/control_comply.cpp` 的原有控制流程读取该故障位。
`ultra_command_node.cpp` 同样用接收时间更新障碍物时效，`ultra_command_comply.cpp`
在启用安全判断时把超过一秒未更新的障碍物输入视为不安全。

因此，本模块断流或处理失败时停止发布，由现有下游超时机制判断故障。持续补发新的空帧
会刷新接收时间，使下游无法区分“真实观测为空”和“上游已失效”。下游文件仅作只读核对。

## 范围与边界

- 本次修改均在 `src/pnc/src/robot_perception_convert`。没有修改消息、PNC 规划/控制、HDMap、启动或地图配置。
- 时效基于 ROS 接收时间；ROS 仿真时钟暂停时，窗口不会按墙上时间过期。
- 按用户先前确认，confidence 仅计算加权出现率，不按阈值删除目标或平滑坐标；消失的历史目标最多保留至最后观测过期。
- 目标按当前输入坐标的轴对齐矩形关联；密集相邻目标仍使用既定的一对一贪心匹配，不承诺全局最优身份关联。
- 本机使用由真实消息定义生成的 ROS 桩，实际 ROS1 通信、部署环境和 Orin 运行尚未验证。

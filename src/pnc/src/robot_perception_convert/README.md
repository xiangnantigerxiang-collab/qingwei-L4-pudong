# 感知转换、目标跟踪与时序滤波

节点已接入 `车道分类与 20% 门槛 → 跟踪与估速 → 两秒原始观测历史 → 按 ID 累计置信度 → 按当前定位重算 type → 置信度与尺寸筛选 → publish`。
`/perception` 发布的对象包含跟踪 `id`、地图速度 `vx/vy`、运动 `heading` 和 `confidence`。
2026-09-17 增加 `/perception/planning` 真实观测输出，供 planning 使用；原 `/perception`
输出规则保持。不修改消息定义、HDMap、monitor 或 control。

## 使用方法

依赖ROS1、已构建的robot消息和本机架构的HDMap库。在车端工程根执行：

```bash
source devel/setup.bash
rosrun robot perception_msg_convert
```

整栈中由 `roslaunch robot robot_canbus.launch` 同时启动转换和can_comm；已有节点时不要重复启动。
需要 `/localization` 和 `/box` 有效输入。地图默认从hdmap包的map_processed加载，启动前可用
`/hdmap/map_processed_dir` 指定目录；加载失败会退出，修改地图后需重启。

```bash
rostopic hz /box
rostopic hz /perception/planning
rostopic echo -n 1 /perception/planning
```

修改源码/`.inc`后重编robot并重启节点；宽长/置信度筛选在下文明确的发布调用处设置。
库函数使用示例见“调用接口”和“置信度与尺寸过滤”。

## 注意事项与容易疏忽的点

- 原/perception含两秒历史，规划专用话题只含真实当前帧；不要用前者是否为空判断起步输入健康。
- 新ID初始零速表示估计未建立，不等于物体已证明静止；vx/vy是地图绝对速度。
- heading是运动航向，物理框四角单独保存；历史type按当前定位重算，不旋转历史检测框。
- 本车道20%用框面积作分母，不是IoU；0.15置信度表示时序出现比例，不是检测概率。
- 有效空帧要参与历史，断流/坏定位不能伪造带新时间戳的空帧；重复时间戳不能反复融合。
- 排除区在前端生效，落入排除区的目标对规划和ultra均不可见；不要把轨迹CSV放进排除目录。
- 4百万米附近float32位置有量化误差；本机零拷贝/缓存性能不能替代Orin实际时延验证。

## 规划专用真实观测（2026-09-17）

复用已有跟踪结果与内部角点，不重复跟踪、分类或复制整包。两个话题均使用 `robot/perception`：

| 字段/行为 | `/perception` | `/perception/planning` |
|---|---|---|
| 对象来源 | 两秒窗内最近真实观测，可能含漏检暂留目标 | 当前有效回调实际检测到的对象 |
| confidence | 按 ID 统计的时序出现比例 | Marker `color.a` 的有限 `[0,1]` 值，未提供为 0 |
| polygons | 保持为空 | 四个世界坐标角点，保留检测框物理朝向 |
| id、vx/vy、heading | 现有跟踪结果；heading 为运动方向 | 同一跟踪结果，不用运动方向替代框朝向 |
| 频率 | 保持原有效回调发布频率 | 稳定空/非空状态最多 12.5 Hz，空/非空切换即时发布 |
| 空观测 | 先经过历史窗与置信度过滤 | 真正空帧，不把历史暂留目标当作新观测 |

新话题在原发布链全部校验成功并提交状态后发布，`header.stamp` 仍为回调接收时间，
不是传感器采集时间；坐标契约是世界地图坐标，原 `header.frame_id` 不另行改写。
超时清理、定位失效和处理失败均不伪造新空帧。尺寸范围由 planning 的输入端检查。
规划状态机和参数见 [planning 感知避障说明](../robot_path_plan/safety/README.md)。

## 跟踪 ID、速度与运动航向

`PerceptionObjectTracker` 位于 `perception_object_tracker.h/.inc`，使用地图坐标系中的
`[x, y, vx, vy]` 匀速 Kalman 模型。每次真实观测前按实际时间间隔预测位置与协方差，
再以中心预测误差和尺寸差异做匈牙利一对一分配，匹配成功后用真实位置修正速度。
输入 Marker 的编号是每帧序号，不作为身份；车道 type 和框的朝向也不作为跟踪身份。

- `id`：使用 `1..32767`，与消息的 `int16` 范围一致；轮转时跳过占用 ID。
  目标持续被观测时 ID 可跨越多个两秒窗口；漏检不足两秒仍可重关联。
  最后一次真实观测达到两秒后释放轨迹，再出现按新目标处理；清空历史不立即重置 ID 分配序列。
  节点重启后重新分配，不保证跨重启身份连续。
- `vx/vy`：地图 x/y 方向的绝对速度，单位 **m/s**。输入位置先用定位转换到地图坐标，
  因此自车移动、转向不应直接成为障碍物速度。使用回调接收时间作为时间基准，与现有历史窗口一致，
  不假定固定输入频率；定位与点云的采集延迟差仍会影响实车估速质量。
  现有 `object.x/y` 为 float32，在约四百万米的地图坐标处精度步长约 0.25 米，
  速度估计会受位置量化影响，尤其在短采样间隔或低速时；本次不改变消息字段精度。
- 新目标在至少两次真实观测、时间跨度达到 **0.2 秒** 前输出零速。
  这表示速度尚未建立，不能仅凭首次零速判定物体静止。
  估计速率 `hypot(vx, vy) < 0.2 m/s` 时对外速度归零，抑制静止目标抖动。
- `heading`：速度有效时使用
  `normalize_degrees(atan2(vx, vy) * 180 / pi)`，范围 **[0, 360)**，
  与 `navigation_msg.heading` 同为北零、顺时针：北 0°、东 90°、南 180°、西 270°。
  零速没有方向，保留最近一次有效运动航向；新目标没有历史航向时，使用检测框世界朝向换算后的方位角
  `normalize_degrees(ego_heading - marker_yaw_degrees)` 作为回退值。

预测位置只用于跨帧关联，发布的 `x/y/dx/dy` 仍取最新真实观测，不将外推框当作新观测加入历史。
漏检期间保留最近估计的 `vx/vy/heading`，原话题的位置仍是最近真实观测；
匀速预测用于内部关联，空帧仅降低置信度，不作为零位移测量修正速度。
`heading` 现在表示运动方向，可能与矩形检测框的物理朝向不同；本模块使用独立保存的世界角点做车道判断，
不根据运动方向旋转障碍框。原 `/perception` 仍保持空 `polygons`，专用规划话题携带四角。

默认参数集中在 `perception_object_tracker.inc`：位置观测方差 `0.04 m²`、初始速度方差
`100 (m/s)²`、连续白噪声加速度强度 `4 m²/s³`。
关联要求预测残差不超过三倍标准差及 `2 + 漏检秒数` 米，真实观测间位移不超过
`30 * 间隔秒数 + 0.5` 米，长短边尺寸比例分别在 `[1/3, 3]` 内。
这些是初始跟踪参数，速度收敛、静止门槛与快速转弯响应需结合实车数据标定。
仅凭位置和尺寸无法保证长时间遮挡或完全重合目标的身份，失联两秒后不猜测旧 ID。

节点先在跟踪器副本上处理；滤波、车道重分类和发布前有效性检查全部成功后才提交状态。
相同时间戳回到该帧前的检查点重算，旧帧仅提供新生目标 ID 的对应关系，不重复融合位置测量；
这样重复帧、数组重排和同时间戳删减目标不会反复增加置信度或污染速度。
时钟回退、非法时间或历史完全过期会同时清除运动状态，异常帧不会覆盖上一次有效估计。

## 本车道重叠比例与历史目标 type

本模块通过现有 `LaneMapServer::ClassifyBoxes` 获取车道分类与交面积，不改变 HDMap 的地图、
车道宽度或通用规则，也不以 monitor 的显示边界作为分类依据。
SDK 按最大重叠面积选中本车道时，额外要求
`本车道交面积 / 障碍框地面矩形面积 >= 0.20`，其中框面积为 `dx * dy`。
正面积重叠不足 20% 时，按当前自车朝向的左右关系改为 `type=3/4`；与所有候选车道均无交面积时由 SDK 判为车道外。
等于 20% 时保留 SDK 的本车道判定；比例比较使用 `1e-9` 容差处理几何计算舍入误差。
这不是 IoU，也不以整条车道面积作分母。左一、左二及其他车道外分类维持 SDK 原规则；
比例不足不会删除障碍物，仍由后续置信度和尺寸条件决定是否发布。

每个目标的位置、尺寸取最近一次真实观测，id/速度/运动 heading 由跟踪器赋值，confidence 按 ID 累计。
`type` 在每次有效 `/box` 回调中按当前定位重算，包含漏检后暂留的历史目标，
防止自车换道或转向后继续沿用旧的本车道标签。原始历史不被重分类结果回写。
无新 `/box` 输入时仍不发布消息。

车道重分类实现在 `perception_lane_classification.inc`。采集时将障碍框的四个世界坐标角点
存入内部历史对象的 `polygons`，时序滤波随最新观测原样携带；发布前清空这些内部角点，
保持原 `/perception` 的 `polygons` 为空，消息定义不变；专用规划话题复用未清空的真实帧。
这样重分类采用框采集时固定的世界朝向，不会用当前自车 heading 或目标运动 heading 旋转历史框。
内部几何缺失或重分类失败时撤销本帧追加并停止本次发布。

## 发布链与历史缓存

`BoxMsgCallBack` 开始时记录接收时间并清理历史，要求已收到定位、定位接收时间距本帧
小于两秒且 `xAxis/yAxis/zAxis/heading` 有限。完成原有坐标转换、排除区域过滤及
HDMap 分类后，跟踪器为本帧真实观测赋予 ID、速度与运动航向，再把带有接收时间
`header.stamp` 的原始观测帧保存到 `mPerceptionHistory`。随后按 ID 累计置信度，
并在发布前校验时间及输出是否来自当前帧：

```cpp
robot::perception filtered_perception = FilterTrackedPerceptionHistory(mPerceptionHistory);
perception_lane_detail::ClassifyLaneTypes(mLaneMap, mGPS, filtered_perception);
// 仅在发布前有效性校验通过、历史提交成功后筛选，允许筛选后的结果为空。
// 尺寸参数按宽度 [下限, 上限]、长度 [下限, 上限] 排列（米）。
mPerception = FilterPerceptionByConfidence(filtered_perception, 0.15, 0.0, 4.0, 0.0, 15.0);
for(std::size_t i = 0; i < mPerception.objs.size(); ++i) {
    mPerception.objs[i].polygons.clear();
}
perception_pub.publish(mPerception);
```

缓存只存带有跟踪属性的真实原始观测，不回存滤波输出或预测目标。空 MarkerArray、只有文字标记的帧，
以及障碍物全被排除区域过滤的帧，也会作为空观测进入历史，参与置信度分母。
时序窗口中的历史目标在最后一次真实观测达到两秒后退出；发布阶段还会剔除
`confidence < 0.15` 的目标，相等时保留。尺寸阈值由调用方传入，目前发布调用的
宽区间为 `[0.0, 4.0]`、长区间为 `[0.0, 15.0]` 米，尺寸本身须大于零；阈值筛选不改原始历史。

缓存按时间递增，回调开始和现有 100Hz 主循环均调用 `MaintainPerceptionHistory`，
移除距今 `>=2s` 的前缀。无输入或持续坏帧也会过期；删除任何历史后都会清除基于旧窗口
计算的本地 `mPerception` 缓存，等待下一真实有效帧重算。相同时间戳只保留最后一帧，
暂停的仿真时钟不会令历史增长；时间非法或回退时清空历史和计算结果，重新建立窗口。

无输入、定位缺失/过期或本帧处理失败时不发布消息；过期维护只清本地状态。
不能用新时间戳持续发布空帧来代替断流，因为 PNC 和 ultra_command 按消息接收时间
判断感知超时，这种空心跳会掩盖上游失效。真实有效的空观测仍正常入窗并发布滤波结果。

坐标转换与滤波均使用局部工作变量，失败不会把半转换数据覆盖到最近的发布结果。
HDMap 分类失败时跳过该帧；时序滤波或历史目标重分类失败时撤销本次缓存追加并跳过发布；
同时间戳旧帧仅在滤波和重分类成功后替换，下一帧仍可使用此前有效历史。若处理期间发生
时间回退、当前帧或定位达到两秒，或滤波返回的 header 并非当前帧，则清空缓存并停止本帧发布。
ROS 时间为零时还检查非空原始帧不能得到默认空结果，避免默认 header 的零时间戳绕过校验。
上述时间窗口均使用 ROS 时间；仿真时钟暂停时，不按墙上时间判定两秒过期。

## 调用接口

节点使用 `FilterTrackedPerceptionHistory(history)`，要求历史对象具有正的、同帧唯一的跟踪 ID。
同 ID 直接累计权重，避免快速移动目标在旧矩形不再重叠时被拆开；不同 ID 即使重叠也不会合并。
该接口沿用原有两秒窗口、指数衰减、空帧分母、重复时间戳处理及最新观测字段保留规则。

原 `FilterPerceptionHistory` 几何关联接口仍保留，供未赋跟踪 ID 的历史数据单独调用：

```cpp
#include "perception_temporal_filter.h"

std::vector<std::pair<robot::perception, double>> history;
// 调用方保存每帧 HDMap 分类结果，时间与 ros::Time::now() 使用同一时钟。
history.push_back(std::make_pair(classified_perception, ros::Time::now().toSec()));
robot::perception filtered_perception = FilterPerceptionHistory(history);
```

输入通过 const 引用读取，函数不修改调用方的历史数据，不跨调用累计观测或置信度。
跟踪版本仅复用工作容量，每次清空上次的 ID 索引；调用仍遵循节点的单线程模型。
调用方负责管理历史容器大小。历史中应保存 HDMap 分类后的原始观测，包括空感知帧；
滤波输出不应再作为新观测放回历史，否则会重复统计已经累积过的结果。

`perception_temporal_filter.h` 提供声明，`.inc` 在现有 `perception_msg_convert.cpp` 中
包含一次并编译。这样无需修改目录外的 CMake，也不需要给消息新增字段：
当前 `robot/object.msg` 已有 `float32 confidence`。

## 置信度与尺寸过滤

```cpp
#include "perception_confidence_filter.h"

// 示例：保留 confidence >= 0.25、横向宽 dx 在 [0.5, 3.0] 米、纵向长 dy 在 [1.0, 12.0] 米的对象。
robot::perception filtered_perception = FilterPerceptionByConfidence(perception, 0.25, 0.5, 3.0, 1.0, 12.0);
```

接口为 `robot::perception FilterPerceptionByConfidence(const robot::perception& tPerception,
double tConfidenceThreshold, double tMinWidth, double tMaxWidth, double tMinLength, double tMaxLength)`：
置信度达到阈值，且 `dx`、`dy` 分别位于宽度、长度闭区间内时保留，任一不满足就剔除。
等于上下边界时保留；上下限相等时，只保留恰等于该正尺寸的对象。
`dx` 按用户定义为横向宽，`dy` 为纵向长，单位米；直接比较尺寸字段，不根据 heading 交换长宽或换算包围框。

保留兼容重载：两参数调用仍只设置信度阈值；原四参数调用的后两项仍为最小宽度、最小长度，
两项上限均不限制。设置区间时，完整传入四项尺寸参数，按“宽下限、宽上限、长下限、长上限”排列。
输入通过 const 引用读取；输出保留消息头、对象顺序和对象所有原有字段，
不重新归一化置信度，不更改历史缓存。空输入或全部被筛除时，仍返回原消息头。

置信度阈值使用传入的有限 double 原值，不做截断、舍入或容差比较；对正常 `[0,1]` 置信度，
阈值为 0 时全部保留，为 1 时只保留值为 1 的对象。NaN/无穷置信度会被剔除；
NaN/无穷阈值抛出 `std::invalid_argument`，避免配置错误被静默转换成空感知。
尺寸下限须为有限非负数，上限不得小于下限，不允许 NaN；上限允许正无穷表示不设上限。
非法区间抛出 `std::invalid_argument`，不自动交换上下界；该检查在处理对象之前执行，空输入同样校验。
对象 `dx/dy` 为非有限值或非正数时直接剔除，即使尺寸下限为 0 也不保留非法尺寸。

实现位于 `perception_confidence_filter.inc`，由现有节点包含一次编译；声明也通过
`perception_msg_convert.h` 引入。筛选遍历一次对象数组，并预分配输出容量，
仅复制被保留的对象。比较耗时为 `O(N)`，另有保留对象（含 polygons）的复制开销。

`BoxMsgCallBack` 已在时序滤波和现有发布前有效性校验通过后调用该函数，阈值固定为
`0.15`，宽区间为 `[0.0, 4.0]`、长区间为 `[0.0, 15.0]` 米，之后发布。需要设置尺寸时，修改调用的第三至第六个参数。
全部被阈值筛除属于有效空结果，不会被误判为时钟异常而跳过发布。
历史缓存继续保存未经阈值筛除的原始分类帧，后续观测仍能与这些目标关联并累积置信度。

相关阶段报告保留于本目录tests；现行完整验证入口见下文“验证”，不把各次累加计数重复列为当前结果。

## 兼容几何关联接口的处理规则

以下描述原 `FilterPerceptionHistory`；节点发布链现由跟踪器负责关联，随后调用按 ID 分组的
`FilterTrackedPerceptionHistory`。以下几何距离/重叠门槛不再限制节点内已建立的跟踪身份。

1. 函数开始只读取一次 ROS 当前时间。保留 `0 <= now - timestamp < 2` 的帧；
   按“2 秒以上丢弃”处理，恰好 2 秒也丢弃。负数、非有限和未来时间戳被排除。
   按时间排序；同时间戳只保留输入向量中的最后一帧，避免重复缓存抬高置信度。
2. 按用户确认，仅用 `x/y/dx/dy` 构造地图轴对齐矩形，`dx/dy` 为完整边长。
   `heading`、`polygons` 和 `id` 不作为关联条件；`type` 的变化也不阻止同一目标关联。
3. 从现有 1 米空间网格的相邻九格中取得候选，再要求中心距离平方 `<=2.0m²`，且
   `intersection_area >= 0.3 * min(area_a, area_b)`；仅边界接触不算重叠。
   该比例对应“覆盖任意一框的 30%”，不是 IoU。兼容函数的这些参数保持原值。
4. 多候选冲突时按中心距离更小、重叠比例更大、原始索引更小的顺序做一对一关联。
   一帧内每个目标至多匹配一次；同帧多个框分别处理，不将其反复计为同一目标的多次观测。
   中间漏帧时可与窗口内最后一次观测重新关联，漏帧不会增加该目标的得分。
5. 每帧权重为 `w = exp(-(now - timestamp) / 1.0)`，衰减时间常数为 1 秒。
   `confidence = 该目标出现帧的权重和 / 所有有效帧的权重和`，空帧也计入分母。
   最后限制到 `[0,1]` 并写入返回对象的 `confidence`，不采用输入对象已有的 confidence。
6. 每个关联目标输出一个对象，保留其最新观测的所有其他字段，包括位置、尺寸、
   HDMap 车道 type、heading、速度和 polygons；输出顺序按目标首次出现顺序。
   返回 header 取最新有效输入帧。没有有效输入帧时返回默认空消息。

该 confidence 表示所给时间窗口内的加权出现率，不是经过标定的检测概率。
只有一帧有效输入时，该帧各目标的 confidence 都为 1；窗口内连续出现的目标也为 1。
时序函数不对位置做平滑、不按置信度阈值删除对象；其输出随后在发布前按置信度和尺寸区间筛选。
几何与 type 在时序函数中均取目标最后一次观测，该函数不重新做 HDMap 匹配；
节点在此函数返回后用当前定位重算 type，再执行发布筛选。

有效帧内的非有限中心、非正/非有限尺寸，以及超出空间索引整数范围的坐标，会抛出
`std::invalid_argument`，不返回部分滤波结果；过期帧在几何检查之前就被排除。
未来时间戳按当前这次调用判断，ROS 时间回退后也不会将未来帧纳入窗口。

## 兼容几何关联接口的计算效率

用 1 米空间哈希网格索引每个目标最新中心，每个输入框只查所在格和相邻八格，
先算中心距离平方，再算矩形交面积。框几何预计算；对象仅保存输入引用，返回时才复制。
目标移动时通过记录桶内位置、末项填补更新索引，避免每帧重新构建全部历史目标的网格。

若输入帧数为 H，有效帧数为 F，有效观测数为 N，第 f 帧在网格内比较 C_f 对框、
通过门限的候选数为 E_f，平均哈希查询下耗时为
`O(H + F log F + N + sum(C_f + E_f log(E_f + 1)))`，
附加空间为 `O(H + N + max(E_f))`。目标密集挤在同一格时，候选比较仍可能退化；
这里采用距离优先的贪心关联，不求解全局最优身份分配。

在工程根执行：

```bash
python3 src/pnc/src/robot_perception_convert/tests/verify_publish.py --output /tmp/perception_filter_publish_verify
python3 src/pnc/src/robot_perception_convert/tests/verify_tracking.py --output /tmp/perception_tracking_verify
```

两条均从当前真实 `.msg` 生成 ROS 桩，以 C++11 和严格警告编译。
第一条编译实际 PNC CMake 感知目标并链接实际 SDK，捕获真实回调传给 Publisher 的消息副本。
覆盖置信度与类型的发布顺序、空帧分母、两秒退出、原始帧缓存、重复/回退时间戳、
100Hz 缓存大小、异常回滚与恢复、CUBE/排除区过滤及五种车道分类，并运行 ASan/UBSan。
另覆盖首次无定位、定位过期/无效、连续坏帧、无回调时实际主循环清理、部分历史过期、
处理期间时钟跳变、零时间戳默认空结果，以及故障时不发布空心跳、不污染有效快照。
发布阈值回归验证当前 `0.15` 等号保留、低置信度剔除、非空输入全部被筛除后的空结果发布，
以及未发布观测仍参与后续置信度累计。
尺寸检查覆盖横向宽与纵向长独立设置、联合筛选、相等及相邻浮点边界、空输入、
非法尺寸/下限、消息字段保留和两参数调用兼容性。
区间检查另覆盖宽/长上限、区间两端、上下限相等、无限上限、上下限反转、非法区间以及四参数兼容性。
车道检查覆盖零重叠、微小正面积、20% 等号与相邻浮点值、左右两侧、旋转框，
以及换道/转向期间的漏检目标重分类、最新观测更新、内部几何异常回滚和对外字段保持。
第二条验证运动估计、八方向航向、静止抖动、停车、交叉目标、漏检预测关联、ID 轮转，
以及不规则采样、地图大坐标精度、按 ID 置信度和分配算法与穷举结果的一致性，另运行 ASan/UBSan 和性能测试。
发布链同时覆盖自车运动补偿、运动航向与框姿态独立、重复帧/重排/删减目标、速度状态回滚及失联重建。
日志及 JSON 结果位于各自指定的输出目录。

原 `tests/verify.py` 与 `temporal_filter_test.cpp` 是兼容几何接口的历史测试，
其中关联门槛期望仍为独立函数阶段的 1 米/50%，与之后已有的源码调参不同；本次跟踪验证使用上述两条命令。

# robot_task_plan 电子围栏（2026-09-22）

任务逻辑在 `task_plan_core.cpp` / `task_fence.inc`，ROS 接线在 `task_plan_node.cpp`。
`fence_geometry.h` 为纯 C++11 校验器，planning 复用它保护最终输出；control 不加载围栏。

## 行为契约

- TRACKPATH、装卸/倒车/入库等行驶任务必须有有效围栏、完整可读路径和安全可达区间。
  缺文件、坏行、退化/自交围栏、起点在外、不可用的短前缀均拒绝：清任务，发布零速/N/NOTHING，
  `TaskStatus.procedure=2, fail_code=2`，`fail_reason` 给出原因。原任务文件错误仍为 fail_code=1。
- 从实际位置的路径最近点开始检查，后续块预检以先前目标为起点；块发布时再用当前位置和文件版本校验。
  顶点及相邻线段都必须在内，压线按外处理；不从首个越界点跳到后面重新入栏的岛段。
- TRACKPATH 遇越界可取第一个越界段之前的安全停止点，并为原车头角点留余量。
  可行区间不足 20 个原始点时拒绝。截停标记一直保留；到达后清除剩余路线/作业，不能当作业务成功。
  动态作业任务若需改写业务终点则直接拒绝，避免在错误位置装卸/入库。
- 保留 ADAPTIVEHOOK 围栏豁免和 DOACTION 无行驶路径的业务。挂钩占位路径缺失不会被新静态预检拒绝。
- task1000 远程目标必须在围栏内，且离所引用路线的最近停车点不超过 2.5m；其它任务仍沿用规划的目标投影语义。
- 每 20Hz 检查导航位置/航向和原前角（后轴参考点前方 2.3m、左右 0.73m）。非豁免行驶实际越界即终止任务。
  导航接收年龄超过 0.5s、倒退或非有限时暂停放行；这不是新增 GNSS 质量判定或完整车身/托盘扫掠模型。
  越界/校验失败须新有效任务重新建立许可，云端“继续”不能解除；云端“停止”下发清空后的终态任务。

## 上下游交接

新增 `robot/task_fence_guard` 消息，既有 task_plan_msg/path_plan_msg/control_msg 不变：

- `/robot/task_plan/fence_guard`：20Hz，包含会话递增 revision、任务字段指纹、围栏/路线几何指纹、批准索引、截停/停车原因、alarm。
- `/robot/planning/fence_feedback`：10Hz，回传同一版本与任务指纹的校验结果和完成标志。
  task_plan 只有收到本代校验与完成反馈才接受行驶块完成，不能用上一块的 TASKFINISHED 推进。
- planning 等待匹配任务与许可后读 CSV、核对几何指纹；截停任务先切出批准区间，再生成连接段，明确用末点停车。
  检查连接/平滑后的实际执行区间及最终发布路径；最终 safety 与既有闸机/感知/急停条件做“或”，不清其它停车来源。
  许可缺失、错代、超过 0.5s 或时钟回退，最终输出 safety=1、desireSpeed=0。
- `/alarmcmd` 改由 task_plan 写：-1未知、0正常、1受阻/越界。HMI 消费带存活的围栏消息；超过1s无新消息显示未知，
  不信任控制节点启动时遗留的参数0。

## 缓存和边界

仅启动/任务装载/块发布时检查文件；20Hz/10Hz 热循环不读盘。目录、文件 inode/大小/纳秒mtime/ctime、围栏几何版本变化使缓存失效。
持久路径缓存最多16文件/200000点，单条组合路线最多200000点，单路径文件32MiB，围栏最多4096顶点/4MiB。
缓存点内状态和同文件相邻段判据。任务检查命中缓存仍是 O(N) 扫描/指纹和 O(N) 临时组合空间，不能称为 O(1)。
运行期位姿判定 O(E)，最终轨迹校验 O(K×E)；通常 D 参考至多60点，E为围栏边数。文件热改在下次任务边界生效，不逐帧监听。

静态预检和 runtime 保护不能代替实车制动距离/定位误差/托盘外廓验收；边界停车效果需实车复测。
既有 task_plan 事件话题不带 latch；planning 重启后无匹配任务时停车，需要重新派发任务。

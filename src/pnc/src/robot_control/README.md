# robot_control 模块说明

该目录实现 `control_node`：20 Hz 接收规划、定位、CAN、任务和交通灯状态，
生成 `/control_msg`，并发布用于诊断的 `/acc`。这里记录文件职责和主流程，便于后续按
业务边界定位修改点。代码格式和改动纪律仍以 `src/pnc/README.md` 为准。

## 实际车速统一使用导航（2026-09-21）

`SetNavigationData()` 将 `/navigation_msg.gpsSpeed` 同步到 `mVehicleSpeed` 和
`/control_msg.vehicleSpeed`；`can_comm` 沿用原转发得到相同导航速度。
`SetCanData()` 不再读取 CAN 速度，仍更新挡位、转角、自动/手动、急停及时效。
因此 D/R 横向和纵向控制、积分补刹、终点缓刹及原 ACC 均使用导航实际车速。

积分补刹和终点缓刹同时要求 CAN 状态、导航消息接收年龄不超过 0.2s；CAN 持续更新
不能刷新导航时间。导航断流时不累计未知误差，已经介入的补刹沿用原保持规则；终点
缓刹条件不满足时返回原 80% 制动。这是回调接收时效，不能检测上游持续重发的冻结测量。
当前工作区标定为 D×13.5、`5.0/13.5` 低速保底，R×10/45% 上限保持。

复核发现，导航 NaN 会直接进入 D 挡转向，出现 NaN 转角和非零驱动，已补有限值检查。
在原 safety、终点/N挡、红灯和空路径停车分支之后、行驶计算之前，NaN/±Inf 触发
零驱动、100%制动、零转角/目标/期望加速度，并清D曲率/补刹/终点缓刹历史。
因此已有终点/N挡的80%保持及其他先行停车规则不被新检查覆盖。有效导航恢复后按原流程处理，
不能解除尚未清除的其他 safety；不回退 CAN 速度。实际速度遥测保留输入读数，不伪造为零。

本轮 C++11 节点桩编译/链接、153 项控制回归、695 项曲率回归通过；另以相互矛盾的
CAN/导航输入核对完整输出、制动及消息转发，见 [专项验证](../../tests/navigation_speed/README.md)。
本机没有 ROS1，本轮未部署车辆；需完整重编 robot 并重启控制及转发节点。
同速度输入下186组/6197条控制消息与切换前一致（仅排除按需求改变的vehicleSpeed上报字段），
异常值与恢复新增210项断言通过，完整证据见 [复核记录](../../tests/navigation_speed/review_20260921.md)。

## 使用方法

在车端工程根、依赖已构建时执行：

```bash
catkin_make --pkg robot -j4
source devel/setup.bash
roslaunch robot robot_control.launch
```

HMI/整栈已经运行control时不要重复启动。节点依赖规划、定位、CAN及任务输入，
launch加载 `param/config.yaml`。调参核对运行值：

```bash
rosparam get /robot/control/brake_integral_threshold
rostopic echo -n 1 /control_msg
```

未设置参数时由源码默认值生效；参数设置/合法范围和更新方式见下文。
当前控制回归入口见下方D挡曲率历史说明；较早80项等计数是历史阶段结果。

## D 挡静态曲率标定与旧预瞄记录（2026-09-21历史）

下列静态C(k)公式仍有效；“峰值立即压到弯速、历史存前方峰值”的动态策略已由本页当前说明替代。

**用户已确认几何曲率抗噪修复通过实车、直线符合要求；后续1.0m/s标定的弯道限速偏低。
现限速曲线取1.0m/s版与更早1.8m/s版的逐点中值，参考点为1.4m/s。
本轮仅将固定6m预瞄改为导航当前车速×4s，限速公式及抗波动策略保持。
尚未实车复测，详见[动态预瞄与验证](../../tests/control/curve_preview_4s_20260921.md)。**

仅D挡的 `ForwardCurveLimitSpeed()` 使用新公式。按上一版0.36/sqrt(k)反推，
参考1.8m/s对应等效k=0.04 1/m、半径25m；这依赖曲率限速为主导约束的假设，
不是实测轨迹半径。新目标替代较早“比0.3系数提高20%”要求，转角本身不决定限速。

先复用本周期 `VehiclePoseCalculation()` 得到的最近点 `mKeyPoint`，在其相邻两段上
计算导航参考点的路径投影，从该投影沿路径向前累计实际折线距离
`L = max(0, /navigation_msg.gpsSpeed) * 4.0`，车速单位m/s、4.0单位秒、距离单位m。
1/1.5/3/4.5/5m/s分别取4/6/12/18/20m，不设最小预瞄距离。零速仍取当前投影曲率并沿用历史；
负速度按0m，非有限导航速度走原安全停车。范围每个控制周期更新，不取planning目标或CAN速度。
取区间最大的绝对曲率，起点和预瞄边界按相邻曲率绝对值插值；前方不足L时止于真实末点，
不补零/外推，重复点不增加路程。按沿线路程取点，不使用数组首点或欧氏圆作为窗口。
`CalcuForwardPathCurve()`在路径更新及进入D时重建纵向缓存：按真实沿线前后各2m取三点圆曲率，
两端平移4m完整窗口、短于4m用可用长度，减少毫米级路径噪声影响。
L限定参与限速的曲率点位置；曲率估计仍有前后2m几何支撑，普通边界处可读取L+2m的坐标，
路径端部仍平移完整4m几何窗口。零速预瞄不等于取消当前位置曲率的几何估计。
原`mPathList`坐标与曲率继续供横向/R使用，D纵向只读取独立`mForwardPathList`。
离开D清有效缓存，重进D或新路径重建；缓存不依赖车速/定位，不必随导航回调重算。

记本次预瞄峰值为 `k_preview`。原30项数组改存每次预瞄峰值，
`k = max(k_preview, 最近30次峰值的均值)`（初始未填位置为0）。新急弯当周期降低上限，
历史仅延缓出弯释放；30次全零输入后完全解除旧弯道影响，正常20Hz约1.5s。
任务/路线/路径编号、挡位/模式和停车复位入口保持，不恢复control起步速度斜坡。

```text
t = clamp((k - 0.005) / 0.015, 0, 1)
c = 0.6 - 0.24 * t² * (3 - 2t)
u = clamp((k - 0.01) / 0.03, 0, 1)
q = u³ * (10 - 15u + 6u²)
v_curve = c * (1 - 2/9*q) / max(sqrt(k), 0.001)     单位：m/s，k单位：1/m
```

- `k <= 0.01`：完整保留上一版直线/微小波动曲线，区间最低上限5.377778m/s。
- `0.01 < k < 0.04`：沿用五次过渡倍率，曲率增大时限速单调下降。
- `k >= 0.04`：上限为0.28/sqrt(k)，参考点1.4m/s，更急转弯和掉头继续降速。
- 各曲率点均取1.0m/s版和1.8m/s版的算术平均，原过渡阈值保持。
- 倍率端点一、二阶导数为0，原曲线与过渡的一阶导数连续；不声称整条曲线二阶连续。
  预瞄中的急弯仍会使入弯前的直线提前限速；未增加降速时间滤波。

用户追加要求的 `if(delta > 0.5) speed_cmd = speed_now + 0.5;` 已在原位置恢复，
随后与曲率、故障限速取小，再执行原低速保底和D×13.5标定。R保留旧曲率函数及最终油门覆盖。
曲率限速仍只降低速度给定，不自行触发规划下降积分补刹；4秒行程不是保证实车完成减速的制动距离。
限速参数为函数内常量，需重编robot并重启control生效，不支持ROS热更新。

本次节点C++11编译/链接、曲率/动态窗口/噪声/5m/s/44组圆弧专项17611项、规划补刹请求/力度16158项、

4901个同曲率限速值与改前完全一致；96组速度/位置/路径对照验证动态窗口，1.5m/s时与原6m完全相同。

## D 挡曲率历史清理（2026-09-20历史记录）

本节为09-20当时的公式与验证记录；当前预瞄、公式和性能以本节上方09-21说明为准。

仅D挡改用 `ForwardCurveLimitSpeed()`；R挡及其他挡位继续调用原 `CurveLimitSpeed()`，
原函数、R横向控制、速度标定、制动和最终油门覆盖不改。D历史为每个控制对象独立的
30个double环形数组，每次D挡限速计算都覆盖一个旧值，不再以曲率变化超过0.001作为更新条件。
连续30次全零直线输入可淘汰全部旧弯道曲率；20Hz正常周期下约1.5秒，不是1.5秒实车加速保证。

仍使用“30个历史值 + 路径数组前30点，总和除以60”，再计算
`0.3 / max(sqrt(平均曲率), 0.001)`。当前取点位置、插值/曲率算法和限速系数均不改。
恒定弯道也会正常填满历史并按该公式收敛，不再保持旧门限导致的冻结值。
清理历史只解除这一来源的旧限制；规划速度、地图限速、制动和safety照常生效。

任务ID/类型/期望挡位、同ID任务的pathList、有效路径Path_Id、CAN挡位或自动/手动状态变化时
清空D历史；无效路径被现有入口拒绝时也清D历史，保留原路径拒绝处理。
停车/退出D入口直接调用 `ResetForwardCurveHistory()`，覆盖safety、N挡、任务停车、交通灯、
空路径、GNSS、横向偏差及D零速度指令。重复同任务、同路径编号、同模式的正常消息不清历史。
清理不写任何safety或刹车字段，也不触碰R历史；不同D控制对象之间不共享缓存。

性能：D函数传只读引用，只遍历固定30项历史和至多30个路径点；相对路径点数N，单次时间/临时
空间由旧O(N)降为O(1)，没有周期堆分配。本机ControlComply由1000变1256 bytes，新增固定256 bytes。
按30项重新求和，避免增量和长期漂移；已清空时复位不再重复写数组。
任务回调仅在D历史有效且既有任务字段未变化时比较pathList，额外最坏O(L)，L为路径名总长度；
现有任务消息复制保持。09-21仅删除 `curvelimitspeed` 和原曲率函数的四条数值转储；
`speed_cmd` / `brake_integral` 制动诊断及停车原因保留。主机耗时和分配对照见workflow，
不据此宣称车端CPU或实际减速效果达标。

业务文件仅 `control_comply.cpp/.h`；两个文件一起同步后完整重编robot、重启control生效。
本轮C++11节点编译/链接及244项控制回归、695项曲率专项通过；回放验证D进入直线后正常释放，

## D 挡行为与注意事项（2026-09-22）

普通起步由planning给定，control保留原速度差上限与保底；减速及减速后的恢复由本页当前D纵向策略协调。
普通液压积分必须有原规划下降授权，再结合电机实测减速度和执行状态决定是否补刹；不再按dec×15直接分配。
D挡safety首帧仍直接零油门100%制动。R不接入D专属积分/液压协调，原控制分支保持。

## 注意事项与容易疏忽的点

- 底层是电机速度环，当前D×13.5/R×10（R上限45），不能按普通油门模型重调。
- 速度误差单位m/s，积分单位m；默认积分上限0.2m不等于固定brakePercent，也不等于实际停车距离。
- 规划下降只是普通补刹的必要条件；还需满足观察、实际减速不足、积分及执行器状态条件。
  曲率波动和恒定目标下的单纯超速不能自行发起普通积分，独立安全制动仍可直接介入。
- `/can_msg.brakePercent`是实际液压响应；请求已撤销不等于实际已释放，不能仅凭欠速或单帧零反馈放行驱动。
- 下游覆盖顺序、挡位、任务、超时和状态重置都是行为的一部分；必须看完整VehicleControl和发布路径。
- 规划目标已降低不等于实际速度已达到；诊断同步观察实际速度、电机参考、积分、请求与液压反馈。
- 积分门槛默认值可被运行参数覆盖；旧三个起步参数和`launch_speed_slope`均已停用。

## 运行数据流

```text
/plan_path_msg ──路径过滤/样条/曲率──┐
/navigation_msg ──车辆位姿与速度─────┤
/can_msg ──挡位/转角/实际液压反馈─────┤
/path_plan_status、/task_plan_msg ────┼─> VehicleControl() ─> /control_msg
/camera/tl_status ──交通灯去抖────────┤
/perception ──可选 ACC/AEB────────────┘
```

`control_node` 当前每周期的调用顺序是：

1. `VehicleControl()` 计算本周期控制量；
2. `PublishMessage()` 发布控制量；
3. 发布 `acc_msg` 诊断信息。

## VehicleControl 主流程

主函数内各段按覆盖优先级排列：

1. 路径安全停车、任务完成或 N 挡停车；
2. 两处场景化交通灯停车；
3. 空路径停车；
4. 计算相对路径位姿、期望速度和期望加速度；
5. 可选 ACC/AEB 诊断计算与基础纵向控制；
6. R 挡几何控制或 D 挡 Stanley 控制；
7. 曲率限速、传感器缓停和 GNSS 急停；
8. D挡协调电机参考、实际液压和驱动承接，保留5%低速保底并按当前标定换算；
9. 冲出跑道横向偏差安全停车覆盖；
10. 输出限幅及R挡油门覆盖；D挡按反馈制动状态约束最终请求，R保留原控制。

后面的步骤可能覆盖前面的控制字段。修改某一业务条件前，应同时检查该条件之后所有对
`mControlData` 的赋值，不能只看局部代码。

## 当前正常末停与积分参数

正常D末停由`forward_brake_control.inc`与主流程协同处理。有效到位证据在状态回调锁存；
同终点、定位和位移核验通过时，距离重算为负不单独切80%。首次进入仍需有效非负距离，
停稳迟滞为进入≤0.03m/s、退出>0.06m/s，连续0.3秒后80%保持，原2秒超时和异常安全覆盖保留。
不从旧09-19说明恢复“速度≤0.05立刻80%”等已替代条件。

默认积分门槛0.1m，参数为`/robot/control/brake_integral_threshold`，经`getCached`运行读取；
非法值按原范围校验回退。积分饱和上限为门槛两倍，默认0.2m。原规划desireSpeed下降是发起条件，
小幅回弹容忍、观察/减速不足确认、真实液压状态共同参与协调，不能从积分值直接推得固定制动百分比。

当前普通首请求3%、上限15%，大/小需求增量和释放条件见本页首节及
[最新专项](../../tests/control/forward_speed_smooth_20260922.md)；独立急停不等积分。
电子围栏不在control判断：批准截停点进入终点流程，越界/路径校验失败由planning叠加safety。

旧dec×50→15调校、积分9%示例及当时终点阶梯已从现行说明移出，原文在

## 修改时必须保留的既有语义

- ROS 话题使用绝对名，include 顺序不调整。
- 不重命名既有标识符，包括 `GeometricConstrol`、`setTaskPlanData` 等历史名称。
- `VehicleControl()` 内逻辑顺序是控制优先级的一部分。
- `PublishMessage()` 在油门和刹车同时非零时会拆成两条消息发布。
- D/R 挡使用不同的横向控制器，不能通过表面相似直接合并。
- D 挡当前 ×13.5、R 挡 ×10 为速度环标定比例（D保留09-21用户修改），起步加速由planning负责。
- 多处算法含跨周期 `static` 状态；移动实现时必须保持函数和静态对象语义不变。
- ACC/AEB 使用 `.inc` 是为了保持原翻译单元；不要直接将它加入 CMake 独立编译。
- `mControlData` 字段赋值是对外协议行为，清理时不能删除。

## 已知但本轮未修改的问题

- `SpeedControl::m_acc_last` 未在构造函数中初始化，而
  `AccelerationCalculateBySpeed_P()` 最终会把它赋给 `desireAcc`。该发布字段会随
  对象初始内存变化；基础油门/刹车当前不使用传入的 `tAcc`，但外部仍可观察该字段。
- `ControlComply::mPathid` 和 `mPathsafety` 也未在构造函数中初始化，首条有效路径消息
  到来前读取它们存在风险。

这些属于既有行为和独立缺陷，当前整理没有擅自初始化；若要修复，应单独做业务影响确认和
新旧场景验证。

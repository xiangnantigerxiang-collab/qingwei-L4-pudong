# robot_path_plan 模块说明

`path_plan_node` 每秒执行 10 次规划，接收任务、定位、CAN 和感知输入，发布
`/refer_path_msg`、`/plan_path_msg`、`/path_plan_status`。编码风格遵循
[`src/pnc/README.md`](../../README.md)：4 空格、`if(condition) {` 同行大括号、原有命名、中文业务注释。

## 实际车速统一使用导航（2026-09-21）

实际速度统一取 `/navigation_msg.gpsSpeed`（m/s）：发布前加速平滑、旧参考轨迹判断、
兼容碰撞加权限速、新感知链的自车速度/制动距离/确认期 60% 限速，以及起步观察。
`/path_plan_status.curSpeed` 由导航回调填写；task_plan 心跳沿用 `curSpeed×3.6` 转为 km/h。
CAN 快照只参与挡位、自动/手动、载荷/挂钩、急停等原业务，不再从中读取实际车速。

起步观察的两帧移动确认由不同接收时刻的导航回调推进，CAN 重发不计票；仍要求 D 挡、
速度绝对值严格大于 0.2m/s、间隔不超过 0.6s，并保留 CAN 状态时效检查。
导航和 CAN 接收频率可能不同，“两帧”不保证与旧 CAN 两帧具有相同耗时。
目标速度、地图限速、障碍物速度、几何距离及既有安全阈值保持原含义。
回归入口及结果见 [速度来源专项](../../tests/navigation_speed/README.md)。

后续复核补充：导航速度为 NaN/±Inf 时，`PublishFinalPlanPath()` 叠加 `safety=1`、
`desireSpeed=0`，覆盖手动/短路径等提前返回及R挡，防止兼容链传出异常目标。
只覆盖本次最终指令，发布后恢复内部原值；导航恢复不清除其他 safety。
日志增加 `invalid_navigation_speed` 原因。该检查不将实际速度遥测伪造为零。
同速度输入下387组状态、635条路径消息和参数事件与切换前一致；详见
[复核记录](../../tests/navigation_speed/review_20260921.md)。

## 使用方法

在已构建的车端工程根目录执行 `source devel/setup.bash` 后，用
`roslaunch robot robot_path_plan.launch` 启动；HMI/整栈已启动规划时不要重复运行。
修改源码需先 `catkin_make --pkg robot -j4`，前提是HDMap、gantry消息等依赖已生成。
启动加载 `param/perception_safety.yaml` 和 `path_dir` 下的CSV；运行值与默认值需分别核对。

```bash
rostopic hz /perception/planning
rostopic echo -n 1 /plan_path_msg
rostopic echo -n 1 /path_plan_status
```

输入还包括定位、CAN与任务。起步不放行看 `plan safety:` 的来源和消息年龄，不能只看
monitor上的障碍物。测试入口见 [规划测试说明](../../tests/planning/README.md)。

## CSV 地图最高限速（2026-09-20）

`path/` 第 4 列为每个路径点的最高限速，单位 m/s，默认 10；D/R 均按当前行驶路径
最近点限速与既有规划速度取较小值。规划推进后及最终发布前分别限制一次，避免后续
速度编排超过上限。0 限速有效，不增加或清除 safety，不提高其他模块已给出的低速/零速。
地图现在仅有x/y/heading/speed四列，旧第五列及CSV变道标志的读取、传递和休眠换道入口已删除；
前三列坐标/方向保持。`speed_limit.csv`对应的独立区域限速已删除。

装载时校验整份地图，三列补speed=10，多列保留前四列，成功后写回原文件；已有四列不重复写。
混合列数也逐行规范化，保留原文本/换行。缺失或无效几何、负限速、无写权限、写入失败或
检测到加载期间文件被修改时，记录错误并返回空路径，原文件不被部分覆盖。
写回使用同目录临时文件和原子替换；文件/目录须可写，软链接目标同步更新。
本项只在任务地图装载时运行，没有新增每周期文件I/O或扫描。

装载 CSV 本身不做重采样。`ConnectVehicleToPath()` 在车距最近路径点严格为 1～2.5 m 时
补连接段，再每 6 点抽稀并按原累计弧长参数以 0.1 m 步长调用样条；这不是最终曲线上
严格等距 0.1 m 的保证。新限速保留连接段跳过的原始点和每个抽稀区间的最低值，
通过单调索引传给重采样点，路径坐标和样条算法保持。每周期的
`BuildReferencePathPoints()` 还会采样前视路径：D挡最多60个真实采样点，其他挡位保留
原里程前视及线段内插值终点；各挡位都不超出真实路线末端。
地图限速直接从 `mDrivingPath[mKeypoint]` 取值，不依赖输出参考点是否被抽稀。

每周期新增两次 O(1) 内存读取/取小，无新增路径遍历、文件 I/O、参数请求或堆分配。
每个内部路径点多一个 float（本机 4 bytes）；一次性连接段限速传递为 O(N+M)，
N 为源点数、M 为样条输出点数。限速随路径对象复制/清除，无跨任务单独缓存；
纯几何生成、无 CSV 来源的路径点默认无限制，保留原作业速度。
缺失或坏路线整段失败，装载失败清空当前行驶路径，避免残留旧限制或跳过缺失路段。

完整格式和生效方式见 [路径说明](../../path/README.md)，
自动保存、功能删除与业务回归见 [本轮验证](../../tests/planning/csv_four_column_verification_20260920.md)。
需同步源码与 CSV，完整重编 `robot` 并重启；本次未增加前方限速区的提前减速规划。

## D 挡前方减速（2026-09-19）

D挡本车道正前方目标，纵向接近速度>1m/s或自身速度<0.5m/s时，制动距离外额外预留3秒；
车头外廓净距6m目标≤0.45m/s、3m及以内目标零速。复用原a/jerk平滑，按实际时间推进，
近段留收敛余量；过近首见时硬限速优先。新限速不改原safety，R不启用。
入口为 `safety/perception_safety.inc::ForwardObstacleSpeedLimit()`，详细条件、参数位置与
几何口径见 [安全README](safety/README.md)。以下较早章节中的旧普通减速距离不代表新增规则的起点。

## 注意事项与容易疏忽的点

- 09-19新增行驶制动仅D，R原后向扫描和控制不改；09-18的R末端修复仍保留。
  09-20地图最高限速按路径生效，D/R均取小。
- 起步半径当前1m，历史2m测试未统一；不要把净距当框大小，也不要只改文档当作参数已生效。
- 普通3m零速与safety判据分开；6m免确认仍需紧迫碰撞条件，不能理解成6m内一律safety。
- `/perception/planning`、type、时间戳及物理角点一起核对，运动heading不等于框朝向。
- 同任务重复消息仍可能重载任务路径；已转换为四列的地图不重复写回，不能假定所有配置均热加载。
- 其他停车来源取OR、速度取min；短路径/手动早退也必须经过最终安全发布覆盖。
- 本机桩/理想速度跟随仅验证实现，实际6m低速和3m停止要看车端控制跟随。

## 每周期的业务顺序

1. `PathPlanProcess()`：补充作业路径，更新最近点，按任务类型计算停车限速与完成状态。
2. `PublishReferPath()`：检查任务/路径有效性，采样参考点，按挡位更新参考路径，发布中间结果。
3. `PublishPlanPath()`：处理人工/短路径退化，复制参考路径，
   平滑加速，叠加急停/断网，生成声光，处理云端暂停，应用地图最高限速，
   发布时叠加闸机安全标志及起步周边停车。
4. `PublishPathPlanStatus()`：发布前面阶段更新后的任务和诊断状态。

最终输出阶段的速度和灯光有顺序覆盖关系。`CopyReferencePath()` 仅复制原有六个字段，
不能改为整包赋值。人工/短路径退化仅发布停车路径，不发布声光消息。

2026-09-18 按用户要求删除旧内部周边/T 路口起步观察及固定等待区停车：不再保留原观察
窗口、通过标志、固定区域坐标和专用报警，也不再因新任务添加约 2.5 秒的观察等待。
旧轨迹复用保留原有长度、碰撞和终点距离条件。外部 `ultra_command` 及其 CSV 不变，
PNC 对 `/ultra/status/safe` 的消费位置保持；起步鸣笛、速度平滑和控制侧速度斜坡保持。

## 手动切自动的起步周边观察（2026-09-19）

`/can_msg.controlPanelState` 从 0（手动）切为非 0（自动，与现有输出门控一致）时建立观察会话，
**仅当前 `curGear == GEAR_D` 时执行观察并覆盖输出**；R/N 挡不增加这项停车条件。
节点启动后第一次收到自动状态也按新自动会话处理。任务切换不重新启用此逻辑。

09-19 行驶制动调整前核对：当前 `startup_observation.inc` 的投影间隙和距离平方阈值
均已为 1.0，即半径 1 米；本轮源码与开工备份完全一致。此前 2 米设计文档和边界测试
尚未同步这一已有变化，本节按当前源码说明；行驶制动调整不修改起步半径。

- 使用 `/perception/planning` 的当帧物理四角，检查前、后、左、右及斜角。
  2026-09-20 起同步剔除 `type=2`（左二车道）；其他车道及左一对向目标仍参与本项检查。
  其余朝向/细长框过滤独立，不受 `AccSwitch` 屏蔽，不等待常规三帧确认。
  有效新帧重新构建本项缓存，全为左二的有效帧按空观测处理；上游排除区仍然有效。
- 按车身矩形与障碍物矩形的**最近欧氏距离 ≤ 1 m** 判定，不按定位点/目标中心的距离。
  车身使用现有 `perception_safety` 的空车/载荷宽度、长度、后轴到前端距离；默认分别为
  3.4 m、3.6 m、2.3 m，属于当前保护外廓，不能当作已经实测的车身/整列托盘尺寸。
  使用未被作业路径改写的原始地图定位。
- 观察期间有障碍时，最终 `/plan_path_msg` 叠加 `safety=1` 和 `desireSpeed=0`；
  新有效帧确认周边无障碍后立即撤销本项停车，不附加固定观察时长，不清除其他停车来源。
  已放行但尚未成功起步时，新出现的近处障碍仍会重新阻止起步。
- **连续两帧导航实际车速绝对值严格大于 0.2 m/s** 才退出观察；等于阈值、无效速度、
  重复时刻或超过 0.6 s 的帧间隔不能凑成两帧。只有 D 挡样本参与，切出 D 挡中断连续计数。
  退出后持续交由常规避障处理，再次停车或任务切换不重入，下一次手动切自动才重新启用。
- 起步尚未完成时 R→D，必须收到回到 D 挡之后的新感知帧才能放行；R 挡移动不能代替 D 挡
  起步确认。D 挡已经完成起步后，同一自动会话中的 R→D 不重新启用观察。
- 切换后先等一帧有效真实观测；切换前/重复/乱序帧不能放行。观察期间感知、CAN、定位
  缺失/无效或超过现有 `input_timeout`（默认 0.6 s）保持停车；有效空帧表示当前无目标。
  畸形检测框使该帧不可用于放行。退出观察后不再施加这些起步专用输入检查。

覆盖位置是 `PublishFinalPlanPath()`，因此也覆盖短路径/空路径提前返回；每次发布后恢复内部
原值，避免起步停车残留，闸机和其他安全来源继续叠加。源码及验证入口见
[`tests/planning/起步观察验证`](../../tests/planning/startup_observation_verification_20260919.md)。
同步规划源码后需在车端重编 `robot` 并重启 `path_plan_node`；没有修改消息或用户配置。

起步不放行时查看规划终端新增的 `plan safety:` 日志（原因改变时打印，持续停车最多每秒一次）。
`startup=nearby_obstacle` 表示命中当前观察范围，并给出目标 ID；`clear` 表示周边检查已放行，
`inactive` 表示观察未启用或已退出。`waiting_perception_planning` 表示尚未收到切换后的有效
`/perception/planning`；`invalid_perception_box/time` 表示框/时间无效；`perception_timeout`、
`pose_timeout`、`can_timeout` 分别表示输入超时。`ages` 是三类消息年龄（-1 表示没有时间记录），
`base/gantry/emergency` 列出其他停车来源，`published` 是本次最终 safety。
监控障碍物显示消费 `/perception`，与起步检查输入不同，不能仅凭监控空场景判定新话题健康。

09-19 最后按用户要求限定当天改动只影响 D 挡：专用感知的 ACC 输入屏蔽修复也仅在 D 挡
生效，其他挡位保留原 `AccSwitch` 门控。R 挡继续使用原后向扫描严格小于 2.5m 的停车规则，
不进入今天增加的前方静态提前减速、3m 急停下限或 6m 免确认判定。

## 任务、路径与停车

`SetTaskPlanData()` 每次收到事件都重载飞机位配置和路径。判断 `task_id` 是否切换后
才覆盖旧任务：切换调用 `ResetTaskHistory()`，同任务的块推进和重复消息保留历史窗、
去抖计数和云端暂停。所有情况都保留急停闩锁。

`calcuGlobalPath()` 的阶段顺序为：

```text
LoadTaskPaths → FindTaskStartPoint → ConnectVehicleToPath → FindTaskStopPoint
     CSV 拼接       寻找起点           生成连接段              寻找停车点
```

初始最近点搜索排除最后 10 点，停车点搜索从第 4 点开始，连接段只在距离原路径严格
介于 1~2.5 m 时生成。周期内 `UpdatePathInfo()` 只向前推进；其上界是会随候选点更新的
`keyPoint + 80`，不是固定的 80 点范围。

`LimitSpeedByDistanceToStop()` 将业务分流到四个规则函数：

| 函数 | 返回速度与完成判据 |
|---|---|
| `UpdateActionTaskStatus()` | 动作任务返回零速，按挂钩状态或无停车点哨兵判断完成 |
| `LimitParkTaskSpeed()` | 按入库剩余距离限速；越过目标方向或不足 0.2 m 判到位 |
| `LimitHookTaskSpeed()` | 使用 `center_distance`，保留托盘连接反馈和距离反增迟滞 |
| `LimitDrivingTaskSpeed()` | 飞机位占用时服从临停线；到最终停车点才结束任务 |

`distance2Stop` 先记录任务终点距离，飞机位临停和挂钩感知距离随后只更新
`remain_distance_`。两者数值可能不同，这是保留的既有发布语义。

普通D终点使用上文09-19的a=0.2、T=4s与末段d/8；09-18的a=0.3、T=3s、d/6
已被替代，详细旧曲线只保留在历史验证报告中。原任务完成与临停释放规则保持。

`LoadTaskPaths()` 同时把多段 CSV 的里程累计为整条 pathList 的连续距离，含段间距离，
避免跨文件里程归零导致提前到位。前向避障完成后再次取原有任务速度上限与避障结果的
较小值，防止兼容避障混合当前车速时抬高终点限速。急停、闸机、断网、暂停等仍按各自
规则立即覆盖。

同日复核补齐 `UpdatePathInfo()` 的真实末点搜索：即使末段点距不小于 0.5 m、CSV 尾部
没有重复点，车辆到终点后也能判定到位，不能继续保持蠕行速度。

## 参考路径与碰撞

planning 在 `/perception` 和 `/perception/planning` 的常规避障入口直接剔除 `type=2/3/4`
（左二、左/右车道外）。左二是 2026-09-20 新增规则，不受目标速度、方向或当前挡位限制，
并同步用于 `/perception/planning` 的起步观察。原 `type=1`（左一车道）动态对向过滤保持：

- 使用 `vx/vy` 地图绝对速度与本车行驶方向比较，不使用可能保留旧值的目标 `heading`，
  也不减去本车速度，避免把同向慢车当成对向目标。
- 速度至少 0.2 m/s（与跟踪器静止阈值一致），且与本车行驶方向夹角大于 135° 才算对向；
  小于 45° 算同向，其余方向不确定。静止、低速、横穿/斜穿均保留；35 m/s 以上或非有限
  速度留给原输入校验，不借过滤跳过异常数据。
- 本车航向沿用定位的北向 0°、顺时针约定；D 挡沿车头方向，R 挡反转 180°。
  尚未收到定位、航向无效或挡位不明时保留目标，零车速不妨碍已知挡位下的方向判断。
- 本车道 `type=0` 不受左一方向规则影响，其他保留目标继续执行既有尺寸、
  几何检查。转换节点和监控端收到的消息不变，独立前后扫描不应用此过滤。

有效新帧将同 ID 改为左二、车道外或左一对向时，立即移除其旧轨迹，不能继续外推；兼容链也清掉
该 ID 的四帧风险历史。新链整帧校验通过后才提交剔除，重复/乱序/坏帧不能部分删除风险。
全被过滤的有效帧仍刷新输入时效。已触发的全局急停仍按原清场迟滞解除，其他独立停车规则
和其他目标的风险不会因本次过滤被清掉。

左二判断复用原遍历及 ID 标记表，不新增容器或消息副本；单目标新增 O(1) 比较。
旧入口最坏仍 O(N+H)，新观测仍 O(N+A)，起步输入仍 O(N)：N 为当前帧目标数，H 为
原四帧历史目标总数，A 为当前活动轨迹数。左二帧可触发原有历史清理分支，清理成本计入 H；
新增持久空间为 O(1)，不因过滤另建历史缓存。验证与复现见
[左二过滤记录](../../tests/planning/left_second_lane_verification_20260920.md)。

planning 在 `/perception` 和 `/perception/planning` 两个入口剔除同时满足
`dx > 1 && dy > 1 && (dx/dy > 3 || dy/dx > 3)` 的细长框；尺寸恰好 1 m 或比例恰好 3
不因本规则剔除，原有其他过滤条件仍生效。利用正尺寸将比例判断写成乘法比较，
在原遍历中执行，无额外容器分配。转换节点的发布、独立前后扫描输入不变；
规划新链中此前有效的已确认观测仍按原漏检外推上限过期，被剔除帧不会刷新它。

2026-09-20 `BuildReferencePathPoints()` 的 **D挡轨迹由原约30点延长到最多60点**。
保留隔点筛选及相邻采样点至少0.3m的条件，路线足够时取满60个真实点，不通过加密凑数。
该数量不是60m或固定时间范围，实际覆盖长度随地图采样间隔变化；在本地
`312_cargo_01_01.csv` 的2214个足够长窗口中，路径折线长度中位数约27.3m，原约13.4m。
这是直接使用当前CSV的主机核对，车端连接段重采样或其他地图可能有不同长度。

其他挡位（含R）保持原规则：以20个采样点覆盖的实际路线里程为基准，前视取1.5倍，
通常约30点，最后一段在原路线线段内插值。各挡位剩余路线不足时均
截止真实末点，不沿航向生成路线外延长线。末端前方点不足 10 个时，补入路线内已走过
的点供控制侧样条拟合；控制前视距离从车辆投影位置开始计算，前方不足时选真实末点。
整条路线仍凑不够 10 点时，最终发布零速空路径，避免控制器拒收后沿用旧轨迹。
当前全局路线不足规划要求的 20 个原始点时，参考缓存也立即清空并置零速，禁止切换任务后
继续发布上一条路线。倒车控制在前方不足 10 个插值点时仍跟踪真实末点，不突然归零转向；
细节和反例见 `tests/planning/today_review_20260918.md`。
R 挡只检查后向扫描目标到后轴定位点的距离，严格小于 2.5 m 时停车。

D挡三个采样数组各预留60项，容量合计720 bytes（float为4 bytes），每次调用内使用，
不增加跨周期缓存；按点数终止后不再计算D挡逐原始段的累计里程。若N为可用原始路线点数，
采样最坏仍O(N)，不增加全路径预扫描；极密/重复点可能需要扫描到末端。D输出上限60点，
没有改变R算法。输出加长会增加消息复制、闸机/兼容碰撞检查及control重采样的数据量；
安全阈值、停车速度曲线和control代码未改，但更远轨迹可能使依赖参考路径的风险更早被检测到。
专用感知链继续按自己的前视距离读取全局路线，不将60点作为新的安全距离。
本机编译/回归、前后耗时和部署文件见 [workflow本轮记录](../../../../workflow.md#2026-09-20d挡单次参考轨迹延长到60点)。

收到首个有效 `/perception/planning` 后，前向检查启用新的真实观测避障：使用真实框角点、
固定 ID 缓存、不同帧确认、`vx/vy` 连续预测和按路径外廓判断，普通风险降低目标速度，
本车道正前方物理净距 ≤6m 的目标，当前真实观测满足紧迫碰撞即可首帧置 `safety`。
其余目标仍需同一 ID 连续三帧紧迫碰撞，前两帧限速为当前导航车速的 60%，
其他更低限速优先；重复规划、漏检外推不累计紧急票数。普通目标确认参数和低分数策略保持，

09-19 行驶制动提前量：反应预留改为 2.1 秒，1 m/s 时紧急判断距离约 3.025 米。

直线、目标/实际速度均为 1 m/s 时，约在车头保护外廓前方 6.9 米产生该旧项限速；09-19新增普通减速还会更早取小。
本车道静态碰撞目标的紧急距离取上述动态距离与 3m 的较大值，防止减速后距离缩小、
紧急票数清零而持续靠近障碍物。6m 是免确认范围，不是所有目标在 6m 处一律急停。
已急停时，尚待确认的紧迫风险也阻止释放；其他解除迟滞和现有起步周边观察保持。
新链启用后不再使用旧的“任意附近目标按中心距离限速”规则，避免绕过路径筛选。
超声停车在新前向链中独立读取缓存参数，不随“感知为空/风险消失”提前跳过；
这项调整防止感知解除时放开另一停车来源。R 挡和独立前扫描原规则保留。
参数、复杂度及适用边界见 [感知避障说明](safety/README.md)。

兼容逻辑在其他挡位先生成前向路径，再依次执行 `CollectReferenceRiskObjects()` 的矩形比较、
`UpdateReferenceRiskHistory()` 的历史保留、`FilterForwardRiskObjects()` 的前方
±90° 过滤，以及 `ApplyReferenceCollisionSpeed()` 的分段限速和三次安全去抖。

## 转向灯与 S 弯抑制优化（2026-09-22）

针对实车在走 S 弯道时转向灯频繁误触发的问题，重构了 `UpdateSoundLightCommand()` 内的 D 挡转向灯决策：
1. **前瞻视野扩展**：由旧逻辑仅取前方第 10 点（~3m）扩展为考察未来 18m 内参考路径演变；
2. **大转角触发门限**：设定最大转向偏角阈值 $\ge 35^\circ$（左）和 $\le -35^\circ$（右），彻底过滤直道纠偏、小曲率弯道和正常循迹；
3. **S 弯反向回摆抑制**：
   - 增加前瞻末端净偏角校验（$\ge 20^\circ$ 或 $\le -20^\circ$），过滤末端回正的 S 弯；
   - 增加反向曲率检测（左转要求最大右偏角 $> -15^\circ$，右转要求最大左偏角 $< 15^\circ$），彻底抑制连续弯道；
4. **状态防抖与保持**：连续 3 周期（0.3s）确认后方点亮；开启后最小保持 1.5s；转弯结束后偏角收敛 $< 15^\circ$ 持续 0.5s 平稳熄灭；
5. **接口协议保持**：`/canbus/light`（0关、3左、4右、5倒车、8双闪/急停）及 `mPathPlanStatus.turning`（"left" / "right" / "none"）完全兼容，R 挡倒车灯与 safety 急停逻辑严格保留。

# 真实观测驱动的前向感知避障

入口为 `CheckTrackedReferenceSafety()`，只用于现有前向参考路径安全检查。
`robot_perception_convert` 发布 `/perception/planning`，规划以队列 1、TCP_NODELAY 订阅，
在原有单线程 10 Hz 主循环使用最新快照，不追赶积压帧。不新增线程或第二个目标跟踪器。

## 使用方法

本目录是规划内嵌算法，没有独立节点。由 `path_plan_comply.cpp` 包含 `.inc`，通过
`CheckTrackedReferenceSafety()` 调用；不能单独把 `.inc` 加入CMake。
在车端工程根source工作空间后执行 `roslaunch robot robot_path_plan.launch`。
该launch加载 `param/perception_safety.yaml`，修改此配置需重启；修改下文局部常量需重编robot。

```bash
rostopic hz /perception/planning
rostopic echo -n 1 /perception/planning
rostopic echo -n 1 /plan_path_msg
rosparam get /robot/planning/perception_safety
```

使用时核对 `/navigation_msg.gpsSpeed`、CAN 的 D 挡/自动状态、定位新鲜度和物理角点；
诊断看 `plan safety:`。09-21 起自车速度统一来自导航；起步移动确认只由导航回调推进，
CAN 继续提供模式、挡位、载荷及时效，不能用 CAN 重发代替两帧导航移动样本。
验证方法见 [规划测试](../../../tests/planning/README.md)。

## 注意事项与容易疏忽的点

- 新前方普通减速只D启用，原safety参数/确认/解除不由普通限速修改；R保持原后向链。
- 6m/3m以车头保护外廓到障碍框近边计；该外廓尺寸未等同于实测车身或整列托盘。
- 起步周边观察是独立逻辑，当前1m，不能把本目录的6m免确认或3m停车当起步半径。
- 空观测与断流不同；重复消息不能累加确认，漏检外推不能当作新真实风险帧免确认。
- 专用话题携带框角点；对象heading是运动方向，不能用它替代物理框朝向。
- 时间平滑不保证晚发现也能物理上平缓停车；硬限速及原急停优先，实车响应单独验收。

## D 挡前方障碍物提前减速（2026-09-19）

`perception_safety.inc` 的 `ForwardObstacleSpeedLimit()` 增加普通限速，仅由适配器在
当前挡位为 D 时启用。对象必须属于本车道 `type=0`、位于当前车头正前方并与车身前向
扫掠外廓横向重叠，同时满足以下任一条件：自车速度减去障碍物沿车头方向的速度严格
大于 1.0m/s，或障碍物自身速度 `hypot(vx,vy)` 严格小于 0.5m/s。

距离从当前车头保护外廓量到障碍物物理框近边，使用空车/载荷对应尺寸；不是目标框尺寸，
也不是定位点到目标中心的距离。函数内常量 `advance_time=3.0` 表示在制动距离之外
额外预留 3 秒行驶距离；`slow_distance=6.0`、`stop_distance=3.0` 分别为低速及零速边界。
6m 处目标速度上限为 `hard_slow_speed=0.45m/s`，严格小于 0.5；6→3m 的上限连续收低，
3m 及以内普通目标速度为零。更低的原业务限速始终优先。原有静态额外 2 秒算法仍保留，
两项限速取小；关闭 `static_obstacle_extra_time` 不会关闭本项 D 挡减速。

提前减速目标先送入原有唯一的 `SmoothLimit()`，按规划周期实际时间限制减速度和 jerk，
不叠加第二个平滑器。默认下降约束为 0.8m/s²、0.8m/s³，恢复加速度为 0.3m/s²；
同一时间戳重复评估不推进平滑状态，长间隔仍沿用原有时间上限和失效处理。
近段目标另留收敛余量，正常连续接近时避免平滑滞后导致速度突降；若首次发现时已过近，
6m 低速及 3m 零速上限优先于平滑约束。既有 safety 急停始终优先。

该项不改紧急距离、三帧/近距免确认、急停保持与解除条件，不写入新的 safety；
独立计算前方距离，不扩展原紧急碰撞检查路径。R 挡、起步观察和 control 本轮未改。
本次限定的是规划目标速度；实际车速能否在相应距离达到要求，仍需结合控制响应实车验证。
修改以上常量后需重编 robot 并重启规划节点，本轮无 YAML 改动。

## 输入和几何

新话题复用 `robot/perception`。每帧仅含当次真实观测，`id` 是现有跟踪器的 `1..32767`；
`vx/vy` 是地图坐标绝对速度（m/s），`heading` 保持北零、顺时针、度的运动航向语义。
`polygons` 的四个点是物理检测框世界坐标角点，碰撞算法只用角点建立矩形，
不以运动 heading 旋转框。当前直接忽略 `type=2/3/4`（左二、左/右车道外），
即使物理框与路径相交也不参与常规避障；`type=0/1`（本车道/左一）保留，左一动态对向
目标仍按既有方向规则剔除。`type=2` 为 2026-09-20 新增的无条件过滤。
两个感知入口同步过滤。有效新观测将同 ID 判为左二、车道外或左一动态对向时，
立即删除该 ID 的旧几何和确认状态，不沿用 0.5 秒漏检外推；旧兼容链同步移除该 ID 的风险历史。
已经触发的紧急状态仍按原解除迟滞退出，其他独立安全来源不被过滤规则清除。

起步观察也在原输入遍历中剔除左二，并随有效新帧清除旧框；起步的其他车道规则保持，
其中 `type=3/4` 和左一对向目标仍按真实周边距离检查。常规跟踪的坏帧/重复帧不能部分
清理旧 ID，全过滤的有效新帧仍更新时效。复用现有缓存和 ID 表，没有新增动态分配点。

原 `/perception` 的两秒历史、置信度和空 polygons 输出保持，继续供旧兼容避障、轨迹复用及其他模块使用。
新话题的 confidence 来自 Marker `color.a`；0 表示上游没有给出可用分数，不能当作高可信概率。
时间仍是转换回调接收时间，尚无采集时刻的定位插值补偿。

首个有效新消息前保留原前向避障，便于启动先后顺序兼容；启用后不再回退历史输出。
重复/乱序时间戳不刷新时效、不增加确认次数。整帧角点/ID 校验成功才提交，坏帧不会部分更新。
尺寸沿用旧范围并剔除退化框：宽 `[0.05,4]`、长 `[0.05,15]` 米。
另外与 `/perception` 入口一致，当 `dx > 1 && dy > 1 && (dx/dy > 3 || dy/dx > 3)`
时剔除当前观测；等于边界保留。被剔除的框不建立/更新轨迹，不导致整帧失效；
同 ID 此前有效的已确认观测仍按原漏检保持规则过期，不会被该框刷新或改写。

## 决策顺序

1. 根据跟踪 ID 累计**不同时间戳的真实观测**。默认连续至少 3 帧且跨度至少 0.2 秒，
   帧间隔不得超过 0.3 秒；正分数低于 0.35 时改为 5 帧、0.4 秒。
2. 未确认目标显式漏检后即删除，不用历史发布把一次误检确认成多次出现。
   已确认目标短时漏检仅按 `vx/vy` 外推，最多 0.5 秒，不重新确认或刷新观测年龄。
3. 从正在行驶的同一路径取有限段，缓存自车外廓、切向、包围盒和距离。起点短连接使用实际车头方向，
   不把定位横误差当作车身旋转；分段切向变化增加旋转包络。
4. 包围盒先排除无关目标，再做连续分离轴检测：求相对运动在四个投影轴上的相交时间区间。
   不进行密集时间采样；同向超车且无未来交叠不停车，预测切入则降速。
5. 普通风险按剩余距离和舒适减速度生成限速，减速/恢复均限制加速度与 jerk。
   本车道 `type=0` 且 `vx=vy=0` 的目标额外预留 2 秒普通减速时间；仍须真实框与行驶路径
   相交，不能仅凭车道标签停车。检查路径同步延长。静态沿用上游已归零的速度判据，
   新轨迹尚未估出速度时也会暂按静态预留；速度变为非零或同 ID 离开本车道后取消额外预留。
   未确认普通目标暂不继续加速，仍允许温和减速。**本车道、当前车头正前方净距 ≤6m**
   的目标，当前真实观测满足紧迫碰撞即可立即置 safety，不等待三帧。使用当前物理框和真实
   车头朝向，要求横向重叠并触及前端平面；侧后方、未来才进入 6m 的预测目标不因此免确认。
   漏检外推不能启动此免确认。其他紧急碰撞仍按同一 ID 累计连续 **3 帧**
   真实风险观测，与普通目标的确认次数/低分数加帧规则独立。第一、二帧只将目标速度限制为
   `min(原规划限速, 0.6 * 当前实际车速)`，不因此新增 safety；第三帧才置 safety 并将速度归零。
   60% 使用每次评估的导航实际车速，不对上一周期命令反复乘 0.6；该上限立即生效，不经过
   普通舒适减速的延迟。其他更低速度、已有紧急保持及其他业务停车优先。
   同一时间戳/重复规划不能加票，漏检、非紧急帧、未评估的中间帧、超出 0.3 秒间隔或 ID 重建
   都会中断连续紧急确认；免确认范围之外，之前已确认存在也不能凭一帧紧急风险直接满制动。
   首个普通余量相交后仍检查紧急距离内的后续段，避免实际碰撞位于下一段时漏判。
6. 本车道静态目标的紧急距离至少 3m，减速至零后仍保持；动态目标及其他车道沿用动态公式。
   紧急状态解除需要风险退出紧急/近距停车范围，并至少两帧新的有效观测、持续 0.3 秒。
   已急停时，即使目标换 ID 尚待确认，只要仍有紧迫风险也不启动解除计时。
   输入断流超过 0.6 秒、无效自车状态或无效检查路径均输出停车。

只使用 `min(原业务速度, 感知限速)` 和 `原 safety OR 感知紧急状态`，不会将其他来源的零速或
safety 抬高/清除。独立前扫描沿用原规则，并在运行后恢复原感知快照；保存原安全标志，
防止其旧计数器清除此前停车原因。新前向链独立读取 `/ultra/status/safe` 的 ROS 本地缓存，
超声停车不随新感知解除而被跳过。缓存 API 初次取值后接收参数更新，见
[roscpp 参数接口](https://docs.ros.org/en/latest-available/api/roscpp/html/namespaceros_1_1param.html)。

最终闸机覆盖、任务停车、云暂停、断网、急停、R 挡扫描与 control 油门标定未改。
非紧迫风险的输出是低速目标；底层减速实际响应仍取决于现有 control 和速度环。

## 用空间减少计算

- 正整数 ID 直接索引固定状态表，同时仅遍历活跃 ID；没有 map 查找、全量关联或新匈牙利分配。
- 矩形轴和半边长在真实观测到达时计算，规划周期只更新位置；路径段只算一次供所有目标复用。
- 复用观测、活跃 ID、路径容量，默认预留 512 个对象和 128 段；扩容后保留，不每帧释放。
- 每次最多 128 段，最多扫描 2048 个路径点；动态预测上限默认 6 秒，检查距离最多 60 米。
- 新话题稳定状态最多 12.5 Hz，空/非空转换即时发布；原话题频率不变。
- 去掉逐目标 yaw 打印，ego 三角函数每帧只算一次；诊断仅在原因改变或风险持续满 1 秒时打印。

设当前对象数为 N、实际候选数为 C、路径段数为 P：更新 O(N)，粗筛 O(N)，精检 O(C×P)，
最坏仍为 O(N×P)，其中 P≤128。不能把密集场景声称为严格 O(N)。核心固定缓存约 4.57 MiB，
300 目标、1000 次预热后“更新＋判断”测试无堆分配；对象超过预留容量时首次扩容仍有分配。
旧感知入口另用 128 KiB ID 标记表清理车道外历史，复用已有遍历，不做两层 ID 匹配。
ROS 收发、原感知历史和独立前扫描的开销不包含在这个零分配结论内。

## 参数与部署

[`param/perception_safety.yaml`](../../../param/perception_safety.yaml) 由
[`robot_path_plan.launch`](../../../launch/robot_path_plan.launch) 加载；启动时读取一次，修改后重启规划节点。

| 参数 | 默认值 | 含义 |
|---|---|---|
| empty/loaded_width | 各 3.4 m | 两种工况的保护宽度，尚未收到实测值，保留旧值 |
| empty/loaded_length、front | 各 3.6 m、2.3 m | 外廓长度、后轴参考点到最前端距离 |
| lateral_margin、stop_margin | 0.15 m、1.0 m | 普通避障外廓余量、停车余量 |
| comfort_deceleration、jerk | 0.8 m/s²、0.8 m/s³ | 普通风险限速下降约束 |
| emergency_deceleration | 0.8 m/s² | 紧急距离公式中的可保证减速度，需按最差载荷实测 |
| reaction_time、emergency_margin | 2.1 s、0.3 m | 普通减速与紧急停车的反应预留、紧急固定余量 |
| static_obstacle_extra_time | 2.0 s | 仅本车道静态碰撞目标的额外普通减速预留，范围 [0,5]，0 关闭此项 |
| static_stop_min_distance | 3.0 m | 本车道静态碰撞目标的紧急距离下限，范围 [0,10]，0 关闭此项 |
| front_no_confirmation_distance | 6.0 m | 本车道当前正前方紧迫碰撞的免三帧确认范围，范围 [0,20]，0 关闭此项 |
| release_acceleration | 0.3 m/s² | 障碍解除后的限速恢复上限 |
| confirmation_hits/time/gap | 3、0.2 s、0.3 s | 真实帧确认与连续性要求 |
| coast_time/input_timeout/clear_time | 0.5/0.6/0.3 s | 漏检外推、断流停车、紧急解除等待 |
| prediction_time/margin_rate | 6 s、0.05 m/s | 动态预测时域及增长余量 |

09-19 按实车约 1 m/s 时刹车过晚的反馈，将反应预留从 0.4 秒调到 2.1 秒。
动态紧急距离为 `v * reaction_time + v² / (2 * emergency_deceleration) + emergency_margin`，
1 m/s 时从 1.325 米变为 3.025 米。后续实测反馈触发本轮修复：旧公式在 0.2m/s 时仅为
0.745m，减速过程可能打断三帧确认。本车道静态目标现取 `max(动态紧急距离, 3m)`，
配合正前方 6m 免确认，在紧迫风险首帧发布 safety/零速，停车后也不会因速度变小而放行。
6m 从车头保护外廓量到障碍物近边，不是障碍物尺寸，也不是无条件刹停距离。
紧急相交保留原有 5cm 几何包络，实际直线触发边界会比计算阈值略早。
本车道静态目标的普通限速另外增加 `static_obstacle_extra_time`，不把该时间加到紧急距离。
在直线、目标静止、目标速度与实际速度均为 1 m/s 的场景，车头保护外廓到障碍物近边
该旧项约在 6.875 米产生限速（含 0.15 米几何余量）；新增D挡3秒/6m低速规则另取更低值，
因此6.875m不是当前整体减速的唯一触发起点。
本次保留 `stop_margin=1.0`、`emergency_margin=0.3` 及解除时间迟滞。
现有起步周边观察、R 挡、其他停车来源和控制标定保持；反应预留的调整适用于所有保留的
前向碰撞目标，额外 2 秒只用于本车道静态目标。普通减速仍输出速度目标，实际减速度需实车验证。

风险诊断额外输出 `ego`（导航实际车速的绝对值）、`stop_distance`（该目标的紧急阈值）、
`hits`（连续紧迫帧数）和 `immediate`（是否免确认），便于与对象 ID/距离一起定位现场问题。

空车/挂托盘由 `can_msg.linkPallet` 选择。挂托盘采用配置的整体保护矩形，尚无铰接角扫掠模型；
应按实际运行外廓设置，不能把未标定的 3.6 m 理解为已经覆盖整列托盘。尚未获实测宽度前，
`type=0/1/2` 的框侵入保护外廓仍会减速/停车，`type=3/4` 则按用户规则直接忽略。

首次接入专用真实观测链需重编并重启 `perception_msg_convert` 和 `path_plan_node`；
09-19仅修改规划普通限速时，重编robot并重启规划节点。消息定义未改。
诊断 `perception risk` 的 reason：0=畅通、1=待确认、2=舒适限速、3=紧迫碰撞、4=紧急保持、
5=输入失效、6=自车/路径无效；同时输出对象 ID、相交距离、TTC、限速、前扫描/原安全标志和计算计数。

开发机验证采用真实算法与由实际消息定义生成的 ROS 桩，详见
[`tests/planning`](../../../tests/planning/README.md)。主机基准不包含 ROS 序列化、调度积压及整车控制时延，
不能等同于 Orin 整车 CPU 降幅。当前尚未在 Orin/ROS1 编译部署或进行车辆试验。

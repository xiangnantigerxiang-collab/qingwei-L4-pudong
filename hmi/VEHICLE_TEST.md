# 车载实测清单(实车验收)

适用:hmi/ 已拷贝到车载 `/home/nvidia/qingwei-L4-No2/hmi/`。
按阶段推进,每阶段通过再进下一阶段。发现问题时先看组件"日志"按钮,
日志目录在 `hmi/logs/<组件名>/`。

---

## 阶段 0:首次预检(只做一次)

1. **确认位置**:`hmi/` 与 `start_l4.sh` 同级(工程根目录下)
2. **相机首次授权**:开一个终端手动跑一次,输入 sudo 密码完成编解码库拷贝后 Ctrl+C 退出:
   ```bash
   cd ~/qingwei-L4-No2/src/driver/cam_geac && ./rb_camera.sh ros1_jpg
   ```
   (或者给 nvidia 用户配这几个命令的 NOPASSWD,一劳永逸)
3. **防火墙放行**:`sudo ufw status`,若 active:`sudo ufw allow 8080/tcp`
4. **确认旧启动方式没在跑**:不应存在 start_l4.sh 的 11 个终端窗口/进程
   (两套同时用会抢 UDP 端口/CAN/master)

## 阶段 1:启动 HMI 与页面自检

```bash
ssh nvidia@<orin-ip>
cd ~/qingwei-L4-No2
bash hmi/hmi.sh          # 建议放 tmux 里跑,便于看服务端输出
```

浏览器(笔记本/平板,与车同网)打开 `http://<orin-ip>:8080`,检查:

- [ ] 顶部**没有**"无 ROS 环境"黄条(有 → hmi.sh 没 source 到 devel,检查是否在工程根目录执行)
- [ ] 14 张组件卡片全灰(已停止)
- [ ] 页脚无"消息包导入失败"红字(有 → 记录内容反馈,对应面板字段会缺)
- [ ] 右栏底部"ROS master"显示未知/正常(此时 roscore 未启,未知正常)

> HMI 服务本身可以一直开着,不受组件启停影响;关掉它组件也继续跑。

## 阶段 2:单组件逐个拉起(先别一键)

按下面顺序逐个点"启动",每次等绿了再下一个。**括号内是判定依据**,
可用另一个终端 `rostopic hz <话题>` 对照页面 health_detail 的数值:

| 顺序 | 组件 | 预期 | 不绿怎么办 |
|---|---|---|---|
| 1 | ROS 核心 | ≤25s 绿(master=正常) | 看日志有无端口占用 |
| 2 | 激光雷达×5 | 绿,详情显示各点云采样 | `rostopic hz /rslidar_points_mid` 对照;雷达 UDP 不通看 config |
| 3 | RTK/惯导 | 绿(/localization) | 串口 /dev/serial_gps 是否在 |
| 4 | CAN 总线 | 绿(CAN 频率≈50Hz) | can_recv 无数据=物理总线/can0 问题 |
| 5 | 相机 | 绿 | **点日志看有无 sudo 报错** → 回阶段 0 第 2 条 |
| 6 | 3D 感知 | ≤120s 绿(首次 TensorRT 加载慢,蓝灯等一会) | 必须在 build/ 目录跑(配置已处理,勿改) |
| 7 | 自动挂接 | 绿(/hook_position) | lakibeam UDP 2368/2369 |
| 8 | 2D 补盲感知 | 绿 | 依赖组件 7 的 /back_pointcloud |
| 9 | 规划控制 | 绿(50Hz/20Hz) | 依赖 3/6 的数据 |
| 10 | 云端网关 | 绿(cloud 节点≥5) | MQTT 连不上云端不影响绿灯,但云端功能不可用 |
| 11 | 行车记录 | 绿(存活即绿) | 看 logData/ 有无新 CSV |

> simview/外网监测/数据录制默认"未启用"(灰显),需要时改 `hmi/hmi_config.py`
> 对应项 `"enabled": False` → `True`(simview 还需确认其工作区路径)。

## 阶段 3:车辆状态面板数据核对(重点,实车独有)

面板数据来自真实话题,**字段映射未经实车验证**,逐项对照:

```bash
rostopic echo -n1 /can_msg     # 另开终端对照
```

- [ ] 车速 = vehicleSpeed×3.6(面板 km/h)
- [ ] 挡位:curGear 2/3/4 → N/R/D
- [ ] 模式:controlPanelState 1/0 → 自动/手动
- [ ] 定位:x/y/航向随 rostopic echo /navigation_msg 变化;RTK 显示"RTK固定"
- [ ] 电量 ≈ 实际;挂接状态文案与实际一致(已挂钩/未挂钩)
- [ ] 急停按钮按下/复位 → 面板红块点亮/熄灭(**静止状态下测**)
- [ ] 障碍物:在车前放障碍物,距离值与实际相符、<6.5m 变红
- [ ] 横向偏差:行驶时小幅变化,不发直线时接近 0

**异常处理**:
- 某字段一直 `--` 且不灰化 → 字段名不匹配,反馈记录
- 某字段灰化(划线)→ 对应话题断流, ages 显示断流秒数
- 组件频繁黄灯且详情显示低 Hz → **真实频率低于配置阈值**,调
  `hmi/hmi_config.py` 该组件的 `min_hz`(本地预设值按标称频率设的)

## 阶段 4:操作与异常处置

- [ ] 单组件 停止→重启 各一次
- [ ] ssh 手动杀一个组件进程(`kill <pid>`)→ 卡片 2s 内变红 CRASHED
- [ ] 全部停止(二次确认)→ 全部变灰;`ps` 确认无 ros/rosbag 残留进程
- [ ] (可选)HMI 暴毙演练:组件运行时 Ctrl+C 掉 hmi.sh → 组件继续跑;
      重新 bash hmi/hmi.sh → 出现橙色"外部"角标 → 点全部停止 → 外部进程被清理
- [ ] 一键启动做"补链":停掉中间某组件后再点一键启动,只补这一个

## 阶段 5:实任务闭环

- [ ] 云端 FMS 下发任务 → 任务状态"执行中"、任务号、子目标点更新
- [ ] 行驶中:车速/挡位/距停车点/障碍物距离实时跟随
- [ ] 倒车对挂时:挂点中心距/夹角有数据
- [ ] 任务完成 → 执行状态"完成"

## 常见问题速查

| 现象 | 处置 |
|---|---|
| 页面打不开 | ping 车端 IP;ufw 放行;hmi.sh 是否在跑;8080 被占则 `HMI_PORT=8090 bash hmi/hmi.sh` |
| 顶部黄条"无 ROS 环境" | 不在工程根目录执行了 hmi.sh,或 devel/ 不存在 |
| 组件一直黄(降级) | 详情里看是哪个话题低频 → 调 hmi_config.py 的 min_hz |
| 相机起不来 | 日志有 sudo 报错 → 阶段 0 第 2 条 |
| 面板字段 -- | 页脚 msg_import_errors;或话题无数据(字段灰化) |
| 想用回 start_l4.sh | 先在 HMI 全部停止,再跑脚本;**两套绝不可同时** |
| HMI 服务想常驻 | 开机自启:`bash hmi/install_autostart.sh`;或 tmux 里跑,或 `nohup bash hmi/hmi.sh >/tmp/hmi.log 2>&1 &` |

## 安全红线

- "全部停止"是**软件停机**,不等同硬件急停;行驶中紧急情况拍车载急停按钮
- 车辆运动测试前确认测试区域封闭、急停按钮可及
- HMI 无鉴权,仅限车载内网,严禁把 8080 映射到公网
